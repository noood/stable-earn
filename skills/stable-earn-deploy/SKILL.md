# 部署 Stable Earn 到 Cloudflare

目标是部署用户指定的 Stable Earn 副本，并核实公开页和私人页的访问边界。需要本机文件、终端和网络能力；登录及私密配置由用户在本机或 Cloudflare 中完成。

## 找到项目和部署目标

- 已有项目时复用，保留未提交改动和私密配置；没有副本时从 `https://github.com/noood/stable-earn` 下载或克隆，不覆盖同名目录。Skill 被单独安装时，先找到或取得项目，不能把 Skill 目录当作仓库根目录。
- 读取该副本的 `AGENTS.md`、`README.md`、[部署指南](../../docs/DEPLOYMENT.md)、[发布清单](../../docs/RELEASE-CHECKLIST.md)和 [SECURITY.md](../../SECURITY.md)。安装、配置、部署和迁移命令以该副本的文档与脚本为准，不维护另一套迁移顺序。
- 确认是首次部署还是升级，并用只读查询核对目标账号、Worker、D1 和 Queue。不能因为本地没有配置就认定远程是空库；发现同名资源时先核实用途。目标有歧义时先完成本地准备，再请用户明确选择。
- 仅在用户明确要求部署或升级时执行对应的远程创建、配置和写入；咨询或编写 Skill 不构成部署授权。已有授权不逐步重复询问；涉及删除、覆盖不明资源或可能丢失数据的迁移时，先说明具体影响并取得相应授权。不附带修改 GitHub 设置、启用收费方案或配置自定义域名。

## 准备环境和配置

- 对照 `package.json` 检查 Node.js，按 README 安装依赖，使用项目锁定的 Wrangler。需要安装工具或系统授权时引导用户完成，不为部署升级依赖或运行强制审计修复。
- 按指南登录 Cloudflare，由用户完成浏览器授权。登录后核对账号，不能将登录成功等同于已选中目标账号。
- 按发布清单完成适用的本地验证；当前候选代码已有有效结果且未受后续改动影响时复用，未验证项明确记录。检查失败时先解决问题，不继续发布。
- 按指南准备账号、数据库及 Access 配置。`scripts/deploy.mjs` 从进程环境读取部署变量，不能只把值写入一个不会自动加载的文件就认为配置完成。真实值只进入被 Git 忽略的本机配置、私密环境或 Cloudflare；不写入 Skill、示例或提交文件。
- 不读取、输出 Secret 值，也不要求用户将密钥贴到聊天。引导用户通过 Cloudflare 的私密输入完成 `CREDENTIAL_ENCRYPTION_KEY` 配置，仅核对是否存在；已有密钥保持不变，不能为消除告警重新生成并替换，否则已有交易所凭证可能无法解密。

## 按数据库状态执行

**首次部署：**按指南创建或复用已确认的目标 D1 和 Queue。只有明确核实为无业务数据的新空库，才按“新数据库初始化”顺序执行 SQL，并检查指南要求的表、列和版本标记。Access 配置覆盖 `/private*`，在填写真实交易所凭证前完成访问保护验证。

**已有部署升级：**先确认备份和实际表结构，再对照指南选择缺少的适用迁移，由单一操作者顺序执行。不得循环重跑全部历史 SQL；带一次性 `ALTER TABLE` 的迁移不能直接重试。指南要求先迁移的，必须在发布新代码或触发自动部署前完成。

- 使用指南指定的 `npm run deploy` 入口。该入口生成私密部署配置并经过 Vinext 构建；不要改为直接用源 `wrangler.jsonc` 发布 `worker.ts`，以免绕过生成的 Worker 配置。
- 首次发布后，按指南完成 Worker Secret 配置；已有部署不轮换密钥。保留定时同步的现有设置，首次部署沿用默认关闭，不顺手启用定时同步。
- 任一步失败时停止依赖它的后续写入。创建资源或迁移的结果不明确时先只读核对，再决定如何恢复；不通过删除数据库、重建资源或重复执行一次性迁移来重试。

## 验证和交接

- 记录部署实际返回的站点地址，不使用仓库演示站点冒充用户的部署。检查 `/` 和 `/third-party-notices.txt`；有浏览器能力时确认页面渲染，否则注明视觉未验证。
- 在未登录状态检查 `/private` 及其 API 子路径不能暴露私人数据，再由用户完成登录，验证私人页可访问。Access 登录跳转是预期行为，HTTP 200 或部署命令成功本身不能证明访问保护正确。
- 生产私人页不应出现开发预览的模拟账号。未配置交易所凭证或钱包时，按正常空配置状态验收；不为验证部署索取交易所 Key、自动运行全平台 API 检查或改写真实持仓。
- 交接站点地址、首次部署或升级结果、已完成的数据库迁移和访问验证，以及仍需用户完成的事项。区分“部署完成”和“真实数据源已接入”，不能把等待登录、缺少 Secret 或验证失败写成全部完成。
