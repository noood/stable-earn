# 启动 Stable Earn 模拟预览

目标是让使用者看到可访问的本地页面，并在交接后继续运行。需要本机文件和终端工具；有浏览器工具时同时确认页面渲染。

## 找到项目并读取启动说明

- 用户已有副本时复用它，保留现有修改与私人配置；无需为了运行而切分支、更新代码或重新克隆。
- 没有副本时，从 `https://github.com/noood/stable-earn` 下载或克隆到合适的本地目录；不覆盖已有同名目录。
- 以该副本 `README.md` 的“本地运行”和 `CONTRIBUTING.md` 的“本地预览”为命令及行为依据，读取项目适用的 `AGENTS.md`。本 Skill 随仓库提供，也可以被其他 AI 直接阅读；不要把 Skill 安装本身作为启动前提。

## 准备环境并启动

1. 对照 `package.json` 的 `engines.node` 检查 Node.js 和 npm。缺少或版本不符时，协助通过官方渠道安装；需要系统授权时由用户完成。不要擅自更换用户现有 Node 环境。
2. 在仓库根目录按 README 安装依赖并启动。已有服务可用时先确认属于此项目并复用；无需每次启动都重装依赖。缺少依赖时使用锁文件安装，不为启动而升级依赖、修改锁文件或运行强制审计修复。
3. 使用仅监听 localhost 的现有开发命令。端口占用时先辨认服务；其他程序占用时按 CONTRIBUTING 选择空闲端口，不终止不明进程。
4. 用用户可控制的终端或能跨回复保持运行的进程会话启动服务，保留停止方式。若工具无法让服务持续运行，把确切启动命令交给用户在自己的终端执行，并明确当前尚未保持运行。

## 预览的项目边界

- 无需 Cloudflare 登录、交易所凭证、钱包地址或真实加密密钥。只为启动预览，不部署、不运行真实 API 检查，不读取 Secret 值，也不改写现有私密配置。
- `CREDENTIAL_ENCRYPTION_KEY` 缺失警告在默认预览中不必然阻止启动；结合后续服务就绪信息与页面响应判断，不为消除警告补真实凭证。
- `/` 是公开演示；开发环境的 `/private` 是模拟账号下的私人页体验，含故意安排的 API 失败、缓存与资料缺失样例，不要将其诊断成真实交易所故障。
- 保存范围见 CONTRIBUTING：持仓、新增/移除产品的保存为模拟；部分产品设置会保存在当前浏览器。不能承诺这里会持久保存个人账本。

## 验证与交接

- 从终端取得实际服务地址。检查 `/` 与 `/private`：有浏览器工具时打开页面，等待加载完成，确认 Stable Earn 导航和产品表格可见；预设的模拟 API 提示可以存在。
- 没有浏览器工具时检查 HTTP 响应，明确说明“服务可访问，页面视觉未验证”，提供地址让用户打开；不把就绪日志或 HTTP 200 当作已验证浏览器显示。
- 保持服务运行，告知项目目录、两个页面的实际地址、模拟数据与保存范围、停止方式（通常原终端 Ctrl+C），以及下次在项目目录重新启动的命令。
- 安装或启动失败时按具体错误处理；需要用户完成系统授权或网络配置时说明阻碍，不通过配置云服务、提供凭证或修改业务代码来绕过。
