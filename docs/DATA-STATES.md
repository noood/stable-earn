# 数据状态与展示规则

本文是产品目录、产品列、持仓列和顶部指标的统一判断依据。界面文案可以微调，但不能改变状态含义。

## 1. 三组状态彼此独立

- `productDataMode`：产品信息来自 API 或人工维护。
- `holdingDataMode`：持仓来自 API 或人工输入。
- `rateCoverage`：APR 与额度信息为 `complete`、`base_only`、`max_only` 或 `unavailable`。

`holdingDataMode` 是产品的默认能力；同步结果中的 `holdingSourceIds` 表示本次页面实际采用的持仓来源，并优先决定是否只读。API 返回持仓（包括 0）或沿用 API 缓存时，持仓只读；只有没有 API 持仓来源且产品允许人工维护时才可编辑。

活期、定期、限时是产品属性，不是新的数据来源。产品同步成功不代表持仓同步成功，反之亦然。

持仓必须区分：

- 明确为 `0`：接口返回零，或完整持仓快照中未出现该产品；
- 未获取：未配置 API、API 失败，或稀疏接口没有给出可判断结果；
- 正数：接口或用户明确提供。

未知值不能按零计算。

## 2. 产品目录准入

所有交易所适配器先返回支持币种的候选产品，统一由目录层判断是否加入。API 产品必须曾经返回有效 APR 才能进入目录；目录保存最后一次有效产品信息，后续单次失败只会改用这份缓存。机会门槛为 `APR ≥ 6%`，短期定期上限为 7 天。

| 候选状态 | 是否进入或保留活跃目录 |
|---|---|
| 人工产品 | 用户添加后一直保留，直到用户删除 |
| 已进入目录且已知持仓大于 0 | 保留，不受当前 APR 门槛、期限、申购状态或资格状态影响 |
| 只有 API 持仓、从未取得有效 APR | 不进入；不使用默认值猜测 APR |
| 账户 API 只提供持仓、产品信息需人工维护 | 正数持仓时建立待补全产品；零持仓不创建默认项 |
| 零持仓或未知持仓的活期 | APR ≥ 6% 时进入 |
| 零持仓或未知持仓的定期 | APR ≥ 6% 且期限 ≤ 7 天时进入 |
| 只知道官网最高 APR | 满足相同 APR/期限门槛时进入，但标记为信息不完整 |
| API 明确已停止申购或账号不合资格，且持仓为 0 | 不进入；已有行可归档 |
| 一次 API 失败、部分失败或单次缺失 | 不据此删除或归档已有产品 |

查看态、编辑态和顶部指标使用同一份活跃目录，不再分别二次过滤。因此表格与顶部机会指标不会引用两套产品范围。

新用户不预置人工产品，也不预置尚未被账户 API 发现的产品。首次进入私人页面时会登记当前用户并立即尝试公开产品同步；之后 08:00、20:00 的计划任务可以继续更新该用户。账户 API 产品只有在配置对应 API、成功发现且取得有效 APR 后才会加入；人工产品由用户主动添加，或在账户 API 确认存在正数持仓但不提供产品信息时建立为待补全项。

仅用于适配器匹配、本地或演示的种子数据不会自动进入真实目录。旧版本遗留、从未取得有效 API APR 的占位产品会在下一次同步时归档并清除旧隐藏标记；以后取得有效 APR 时仍可作为真实产品重新进入。

## 3. 产品身份与生命周期

每个 API 产品保存平台原始 ID、内部身份键和身份指纹。普通 APR 或额度变化不会创建新产品；定期产品的申购开始、申购截止或期限发生变化时视为新一期，创建新行。

- 新一期可以与仍有持仓的旧一期同时存在。
- 旧一期只有在完整持仓快照确认持仓为 0 时才可归档。
- 已停止申购但仍有持仓的产品继续显示，并按已有产品数据计算。
- 用户删除旧一期，只隐藏该期；未来的新一期使用新内部 ID，仍可正常出现。
- 归档只改变当前目录展示，产品行与历史数据不因一次同步缺失而物理删除。

## 4. 产品列

产品列只负责 APR、额度、期限、申购时间、资格描述、来源和完整性，不显示持仓错误。

| 产品状态 | 查看态 | 编辑态 | 收益计算 |
|---|---|---|---|
| API 信息完整 | 展示 APR、额度及产品属性 | 同样只读；无其他提示时显示“来自 API” | 持仓条件满足时参与 |
| API 失败但有缓存 | 展示已知信息及“产品信息沿用 … 的缓存数据” | 同上 | 使用缓存参与 |
| API 数据不可用 | 对应字段显示“待获取”并列出具体缺失项 | 只读 | 不参与 |
| 只有基础 APR | 展示 APR 与“首档额度待确认” | 只读 | 不参与收益；APR 可参与最高 APR 比较 |
| 只有最高 APR | 展示“官网最高”与“阶梯结构待确认” | 只读 | 不参与收益或额度；可参与最高 APR 比较 |
| 人工信息完整 | 展示已填写信息 | 显示输入项 | 持仓条件满足时参与 |
| 人工信息缺失 | 展示具体“待填写”项 | 显示输入项及同一缺失说明 | 不参与 |

缺失说明按实际字段生成，例如：

- `APR 待填写，不参与收益计算`
- `首档额度待确认，不参与收益计算`
- `锁定期限待获取，不参与收益计算`
- `买入日待填写，不参与收益计算`

存在缺失说明时不再同时显示“来自 API”。需要买入日的定期或限时产品，只要买入日为空，就显示买入日缺失，无论持仓为 0 还是正数；它只阻止收益计算，不阻止产品参与最高 APR 或已知额度比较。无持仓时缺失说明使用中性色，有正数持仓时使用 warning 色。

资格信息不再使用 checkbox：

- API 明确返回资格要求时，在产品属性中展示资格名称；
- API 无法判断账号是否合资格时，申购资格显示“待确认”；若资格名称已知则显示“资格名称 · 待确认”。它不属于产品信息缺失；
- API 明确不合资格且持仓为 0 时，产品不进入目录；若仍有正数持仓则保留并显示“账号不符合资格”。

用户用实际行为表达判断：填写完整产品与持仓表示正在使用；保留零持仓表示继续关注；删除表示不适合或不再关注。

## 5. 持仓列

持仓列只负责金额、额度使用、缓存和持仓同步原因，不重复产品完整性或资格描述。

| 持仓状态 | 查看态 | 编辑态 | 计算 |
|---|---|---|---|
| API 正数 | 完整展示“持仓 / 首档或申购额度 + 进度 + 剩余额度” | 上方只读框显示金额与“来自 API”，下方保持同一完整摘要 | 产品完整时参与 |
| API 明确为 0 | 展示 `0.00` 及完整额度摘要 | 只读框与同一摘要 | 无收益，可参与已知额度比较 |
| 人工持仓 | 展示已保存金额及完整额度摘要 | 显示输入框与同一摘要 | 产品完整且大于 0 时参与 |
| 产品信息不完整 | 显示已知持仓金额，但不显示进度条、额度或剩余额度 | 只保留输入/只读框；不在下方重复金额 | 不参与收益 |
| 持仓失败但有缓存 | 展示缓存金额并注明“持仓沿用 … 的缓存数据” | 同上 | 产品完整时使用缓存参与 |
| 未配置 API且无缓存 | “持仓未获取” + “未配置 API；配置后可同步持仓” | 只读框显示“未获取”，下方只保留同一句原因 | 不参与 |
| API 同步失败且无缓存 | “持仓未获取” + “API 同步失败” | 只读框显示“未获取”，下方只保留“API 同步失败” | 不参与 |
| 稀疏接口无明确结果 | “持仓未获取” + “接口未返回该产品持仓” | 只读框显示“未获取”，下方只保留同一句原因 | 不参与 |

产品不完整时，查看态仍保留已知持仓金额和缓存时间，但隐藏依赖产品信息的额度摘要；编辑态只依靠输入框避免重复金额。查看态与编辑态使用完全相同的同步原因，未知持仓仍显示“持仓未获取”及具体原因。

查看态中，明确为 0 的持仓统一使用弱化行样式；持仓未知或未获取的产品不置灰，避免把“未知”误读为“没有持仓”。

## 6. 顶部指标

| 指标 | 使用范围 |
|---|---|
| 总持仓 | 活跃目录内持仓已知的全部产品 |
| 组合有效 APR / 每日收益 | 持仓已知且大于 0、APR/额度/必要期限完整、所需买入日已填写 |
| 最佳首档 APR / 最高公开 APR | 活跃目录内 APR 已知的产品；无需持仓，不因买入日或资格未知排除 |
| 高息剩余额度 | 活跃目录内 APR ≥ 6%、首档或申购额度上限已知、持仓已知的产品；包括活期和定期，不要求买入日 |
| 超出首档 | 活跃目录内首档上限和持仓均已知的产品 |

已到期、停止申购或明确不合资格但仍有正数持仓的产品继续留在活跃目录，因此仍按原产品数据进入顶部指标；页面通过“已到期 N 天”等状态提醒用户自行删除或继续保留，不自动改写利率或收益。

## 7. 查看态与编辑态

- 两种模式展示同一目录、同一产品说明和同一持仓说明。
- 编辑态只增加可编辑字段、删除入口及操作按钮，不引入额外产品。
- API 产品字段保持只读；人工产品字段可编辑。
- API 设置同时存在于右上角常规菜单和编辑态副标题入口；可配置 Key 的平台在前，MEXC 等手动维护平台直接接在同一列表底部且没有配置入口。
- 公开页的 API 设置入口先进入登录流程，登录后的私人页自动打开设置。
- 查看态与编辑态切换时避免不必要的布局跳动；标题信息和操作相近时保持视觉高度稳定，内容确需更多空间时允许自然增高。
- 删除先显示二次确认：`删除后将不再记录该产品的持仓和收益，是否删除？`
- 删除只修改当前草稿，点击“保存持仓”后才写入；取消编辑会恢复。

## 8. 同步、缓存与重试

计划任务每天上海时间 08:00 和 20:00 运行。已配置平台出现错误或部分成功时，初次失败后等待 1 分钟重试，再失败后等待 5 分钟进行最后一次重试。

- 前两次候选结果只存在内存并写运行日志，不修改产品目录、缓存或页面错误状态。
- 任意一次完全成功时，将目录和缓存一次性提交。
- 最后一次仍为部分成功时，才提交该部分结果及现有错误说明。
- 最后一次完全失败时，保留最近成功缓存并写入现有错误状态。
- 手动刷新不执行分钟级重试。
- 顶部提示按接口实际能判断的粒度汇总：整个平台失败显示平台名，独立币种请求失败显示“平台 + 币种”，Bybit 聚合定期接口失败显示“Bybit.com 定期产品”或“Bybit.com 定期持仓”。接口成功但未返回某个产品不冒充为币种请求失败。

目录写入与缓存写入使用同一次数据库批处理，避免页面读到“目录已变、缓存未变”的中间状态。

## 9. 本地验收数据

本地私人预览长期保留全量状态样本，包括：完整/缓存/基础 APR/最高 APR/不可用、明确零/正数/未知/同步失败持仓、APR 等于 6%、低于 6% 但有持仓、7 天与长定期、停止申购但有持仓、不合资格但有持仓、同平台 ID 的旧新两期，以及买入日缺失时 API 持仓和人工持仓两种来源。
