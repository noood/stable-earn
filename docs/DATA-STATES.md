# 数据规则与测试

## 数据来源

- `productDataMode`：产品信息由 API 或人工维护。
- `holdingDataMode`：默认持仓来源；`holdingSourceIds` 标记实际采用的 API 持仓。API 返回值及其缓存只读，不能因产品信息需要人工填写就开放持仓编辑。
- `rateCoverage`：`complete`（完整）、`base_only`（仅基础 APR）、`max_only`（仅最高 APR）、`partial`（已知档位未覆盖完整额度）、`unavailable`（不可用）。

平台 × 资产 × 活期/定期的 API 覆盖盘点与目标产品筛选规则见[平台能力矩阵与筛选规则](PLATFORM-CAPABILITIES.md)。矩阵中的 `manual` 表示当前例行同步不调用该接口，不代表已证明交易所不支持。

产品与持仓分别判断。持仓的正数、明确零、未知不能混用；只有完整持仓快照才能把未出现的产品判为零。产品字段缺失不抹掉已知持仓，持仓失败不抹掉有效产品数据。

## APR 与额度必须分开判定

不同平台对“单一利率”和“按金额分档”的表达不同。按已确认规则，单一 APR/APY 没有返回 APR 适用金额上限时按不限额处理；若 API 另返回明确的产品累计申购上限，则按该上限限制。单笔申购上限不代表账户累计额度，也不作为高息额度边界。多档产品则必须把每档金额边界看完整。平台字段和本次回包已合并记录在[平台能力总表](PLATFORM-CAPABILITIES.md)，统一计算口径见[APR 与额度规则](API-APR-CAPACITY-RULES.md)。

统一原则：

- Binance 活期：基础 APR 加对应奖励档 APR；奖励档之外继续按基础 APR。基础 APR 有效但没有奖励档时，仍按基础 APR 覆盖全部金额。
- 其他平台：单一 APR/APY 或各档 APR/APY 直接使用，不叠加。单一利率没有返回 APR 适用金额上限时按不限额处理；若 API 另有明确的产品累计申购上限，仍遵守该上限。单笔申购上限不当作累计额度。
- 多档产品必须逐档检查 APR 和金额边界。每档边界都返回时按原值计算；最后一档上限未返回时，有产品总上限就用它补齐，没有产品总上限就按最后一档不限额处理；明确返回 `-1` 也按不限额处理。字段已返回但值不可解析时仍是不完整，不能当成上限未返回。
- 交易所数字字段必须整段符合数字格式才接受；例如 `1000abc`、空字符串或 `null` 不能被截成 `1000` 或 `0`。APR 缺失不等于 0%；额度字段不可读时不推断为不限额。只在已确认的字段上接受平台格式，例如 Bybit APR 的末尾 `%` 和 Binance APR 的百分数写法；去掉符号只是读取数字，APR 单位仍按对应平台规则解释。梯度上限的 `null` 按“未提供该档上限”处理；产品申购上限的 `null` 不按不限额处理。
- 多档最后一档明确返回有限上限，但产品总额度更大或为不限额时，已知档位不足以覆盖整笔持仓；保留已知档位，标记 `partial`，不计算整笔收益。若最后一档上限字段未返回，则按前一条处理，不套用这个“已知有限上限”的情况。
- 只解析出一档、但产品明明是多档时，不足以判完整。出现缺档、坏边界、断档或重叠，且不能按已知总上限补齐时，相关收益/额度计算暂停并标明缺失项。
- 利率适用范围的“无限”不等于当前可买量无限。产品申购上限、产品池余量和账户已占用额度分开记录；只有当前可买量的口径清楚时，才用上限减已占用金额。

## 目录与身份

完整的 ID 职责、格式和生命周期见[产品身份与 ID 规则](PRODUCT-IDENTITY.md)。本节只说明目录如何使用这些身份。

适配器返回候选数据，`lib/product-catalog.ts` 统一维护用户目录；查看态、编辑态和顶部指标使用同一活跃目录。

| 候选产品 | 目录规则 |
|---|---|
| API 活期机会 | APR ≥ 6% |
| API 定期机会 | APR ≥ 6%，且期限 ≤ 7 天 |
| 已有正数持仓 | 保留，不受机会门槛、期限或申购资格影响 |
| API 信息从未有有效 APR | 不创建占位产品 |
| API 仅提供持仓、产品信息需人工维护 | 正数持仓时创建待补全项；零持仓不创建 |
| 用户手动添加 | 保留到用户删除 |
| 明确停售或不合资格 | 已知零持仓可归档；未知持仓不据此清除已有行 |
| 单次失败或产品缺失 | 不据此自动归档 |

种子模板只用于匹配、演示和测试，不预置进真实用户目录。历史占位清理使用一次性迁移，不增加运行时特殊分支。

平台原始 ID 用于对应上游产品；内部 `identityKey` 用于关联同一产品。优先使用“交易所/账户区域 + 资产 + 稳定外部 ID”；上游没有外部 ID 时才使用适配器提供的稳定回退键。APR、额度、资格、申购窗口、买入/赎回时间都属于会变化的资料，不参与产品身份。产品列表暂时不返回但持仓接口仍返回时，若 ID 能对应到已知目录项就沿用原行；若是首次出现的正持仓且身份可识别，则按“API 持仓 + 人工产品资料”创建待补全行。身份不明确时不猜测、不拆分币种总额。归档保留数据库记录，不等于物理删除。

## API 结果状态与持仓产品降级规则

将 `empty`、`partial`、`error` 分开记录；状态针对一次明确的“平台账号 × 币种 × 活期/定期 × 产品/持仓”请求，不代表交易所所有产品线永久支持或不支持。

API 请求状态与产品行是否具备完整计算资料分开判断。请求本身成功、查询范围完整时，不因某一产品缺少 APR、额度、期限或买入日期等资料而报告 API 请求失败；在对应行说明缺少什么，并暂停依赖该资料的收益或额度计算。API 本应提供的必需字段缺失时，顶部沿用警示样式，列出平台、产品和具体“未获取”字段，但请求状态仍为成功。只有查询本身失败，或分页、查询范围、必要身份等导致整份结果不完整时，才把 API 状态标为 `partial` / `error`。字段是否需要补充，由产品计算需要决定；字段由 API 提供还是由用户填写，则按平台字段能力决定。

活期不需要买入日期或锁定期限；APR 必须有效，额度范围必须能从接口数据或已确认的额度规则中判定（例如已确认的“不限额”），否则该行提示补充。单一 APR 或多档末档按已确认规则不限额时，不因未返回上限报错。定期还需要产品期限；已有持仓时，需要买入日期或等价的 API 持仓时间来判断到期，尚未申购的产品不要求买入日期。API 支持但本次缺失的必需字段显示“未获取”并保持只读；API 不支持且计算需要的字段显示“待填写”。两类字段同时缺失时逐项列出；APR 明确返回 0 不属于缺失。

| 状态 | 判定 | 产品接口处理 | 持仓接口处理 | 用户提示 |
|---|---|---|---|---|
| `returned` | 请求成功、查询范围完整，返回一行或多行；单个产品字段是否足够计算另按产品行判断 | 使用可识别资料；缺少计算所需字段时在该行提示，不计算依赖该字段的收益 | 按稳定产品身份合并持仓 | 请求正常；产品行提示“未获取/待填写”，API 必需字段缺失时顶部也列出具体产品和字段 |
| `empty` | 请求成功且结果完整，但当前查询范围没有行 | 记为“本次无相应产品”，不因空列表报错；没有正持仓时不创建占位产品 | 对已知产品，只有在完整、权威的持仓快照下才可把缺失行推断为 0；否则保持未知 | 不显示 API 失败或“部分数据未返回” |
| `partial` | 请求有响应，但整份查询结果不完整：分页未完成、查询范围不全、必要身份缺失或无法安全配对 | 保留已确认资料，不把缺失部分当作不存在；产品行资料不足时按上方规则提示，不计算依赖缺失资料的收益 | 保留已知正持仓/缓存，不把缺行补成 0 | “部分数据未返回”；不要把单个产品字段待补充说成 API 请求失败 |
| `error` | 请求超时、网络/权限/API 错误，或响应无法解析 | 不把失败当作空产品；沿用可用缓存 | 不覆盖已知持仓、不推断为 0 | “API 暂不可用”或更具体的失败原因 |
| `not_configured` / `not_integrated` | 缺少可用凭证，或代码没有接入该请求 | 表示本项目当前拿不到，不是一次成功空响应 | 不代表零持仓 | 按“未配置”或“当前未接入”说明；不能伪装成 `empty` |

产品与持仓的组合规则：

1. **产品请求完整成功、无产品行，持仓也为空：**不创建产品，不报错。
2. **产品请求完整成功、无产品行，但持仓为正且身份可识别：**保留已有同身份目录行；首次出现则创建“产品资料人工维护、持仓 API 更新”的待补全行。APR、额度、期限或买入时间等必需信息没补齐前，不参与收益计算，也不报产品 API 错误。
3. **产品请求失败或不完整，但持仓为正：**保留该持仓；显示对应 API 失败或部分返回提示，不将未知资料说成“没有产品”。
4. **币种汇总余额与多个同币种产品无法区分：**只保留一个币种汇总行，不把同一总额复制到多个产品，避免重复计算。若项目在该币种只跟踪一个活期产品（当前 OKX USDT、USDC、BTC），完整有效的币种汇总可一对一映射到该产品；完整回包中缺少该币种行按零持仓处理。

成功但空的产品列表只表示本次账号/币种/期限下没有返回产品行，不能单独证明接口不支持。若平台在该产品上没有可用 API，能力盘点可按项目既定口径标为“本项目 API 不支持/人工维护”；不要把它编码成一次请求的 `empty`。探针状态与日常同步状态也必须分开：探针显示 `empty` 不代表日常同步一定正确处理空结果。

Binance 活期和 Bybit 产品扫描只有在请求及分页完整、且结果列表确实为空时，才按 `empty` 成功处理。接口返回了可识别的产品行，但该行缺少 APR、额度或其他计算资料时，在产品行按来源显示“未获取”或“待填写”，并暂停依赖它的计算；不因此报告 API 请求失败。若缺少产品身份导致无法判断该行属于哪个产品，或分页/查询范围不完整，则本次结果为 `partial`。Bybit 定期同样要求分页完整；后续分页失败或不完整不能伪装成空结果。完整空结果只表示“这次没有返回产品”，不能据此把持仓判为零。

API 定期持仓的 `purchaseAt` / `redeemAt` 单独保存，不写回产品身份。展示态只显示“预计 09/16 到期”“已于 09/16 到期”或“到期日未获取”。各适配器声明字段能力：API 支持的时间字段缺失时保持只读并显示“未获取”；API 明确不支持的字段沿用现有手动输入框。手动产品仍使用用户填写的买入日。API 时间戳展示按上海日历日期转换；用户填写的纯日期保持原值。

## 两列状态与计算

| 状态 | 页面处理 | 收益/机会指标 |
|---|---|---|
| 产品完整，持仓已知 | 展示产品信息及持仓摘要 | 正数持仓参与收益 |
| 单一 APR/APY 有效，或 Binance 基础 APR 有效但没有奖励档 | 显示该利率；按单一利率/基础 APR 估算已知持仓收益 | 没有金额档位时，按利率覆盖全部金额；若另有产品申购上限，再单独处理 |
| 多档 APR/APY 的档位范围完整 | 显示各档利率和金额边界 | 各档按实际占用本金计算收益；只把达到高息门槛的档位计入高息额度 |
| 多档 APR/APY 缺档、边界无法读懂或范围不连续，且无法用产品总上限补齐 | 显示已知档位与“阶梯结构未获取” | 不计算依赖缺失范围的收益和高息额度；不把坏边界当成无限 |
| 人工字段缺失 | “APR/额度/期限/买入日待填写” | 不算收益 |
| API 必需字段不可用 | “具体字段未获取”，保持只读；顶部点名平台、产品和字段，但不改变请求成功状态 | 不算收益 |
| 产品失败但有缓存 | “产品信息沿用 … 的缓存数据” | 用缓存产品数据计算 |
| 持仓失败但有缓存 | 保留金额，“持仓沿用 … 的缓存数据” | 产品完整时用缓存持仓计算 |
| 未配置持仓 API、无缓存 | “持仓未获取”；原因“未配置 API；配置后可同步持仓” | 不算收益和剩余额度 |
| 持仓失败、无缓存 | “持仓未获取”；原因“API 同步失败” | 同上 |
| 接口缺行且该范围未配置为可判零，或本次结果不完整 | “持仓未获取”；原因“接口未返回该产品持仓” | 同上 |
| 明确零持仓 | 展示金额与已知额度，查看态统一弱化 | 无收益，可比较额度 |

产品资料缺失时，持仓列保留已知金额及缓存提示。首档额度和边界已知时，仍显示首档额度、使用进度和剩余可放金额；买入日期、期限、APR 或后续档位待补，不遮蔽已知的首档额度。缺少首档额度或边界时，隐藏首档进度与剩余额度；后续档位不完整且持仓超出首档时，只提示“后续档位待确认”，不声称超出部分已按某个 APR 计息。只暂停依赖缺失字段的计算：例如买入日期缺失时不算定期收益，但不影响已知额度的展示。若只是单一利率没有金额档位，不算资料不完整。编辑态使用输入/只读框，不在其下重复孤立金额。两列不互相重复错误原因。

### 产品变更时间轴与红点

变更事件共用 `product_change_events` 一张表，按产品使用游标分页读取；不因历史增长拆表，也不会因为首屏只读一页而丢失旧记录。

未登录演示页使用两条固定的合成变更记录，不请求或复用任何账户历史，也不写入数据库。

时间轴记录已确认的实际变化：

- API 数据：APR/阶梯变化、首档额度变化、申购状态变化、期限或认购截止变化、明确持仓金额变化，以及定期到期日变化或到期。
- 手动编辑：持仓、APR、首档额度、期限、买入日期及手动产品资料变化；手动定期持仓到期也会记录。
- 初次快照没有可比较的前值，不生成差异记录。由缓存回退的数据、未知持仓或未知额度不冒充本轮确认变化。

红点只表示该产品有尚未读过、需要关注的事件：

| 关注事件 | 触发条件 |
|---|---|
| APR 跌破门槛 | 首档 APR 从 ≥6% 降到 <6%；上调或持续低于 6% 不触发 |
| 持仓超过首档额度 | 已知持仓严格大于已知首档上限，且此前不在超额状态；等于上限不算超额 |
| 定期到期 | 定期持仓首次跨过到期日，或首次发现时已到期；手动定期仅在持仓大于零时提醒 |

普通持仓增减只记录在时间轴，不触发红点。首档额度变化、APR 上调/持续低于门槛、申购状态变化、期限或买入日期修改本身也不触发红点；若额度变化同时令已知持仓进入超额状态，则另记录一条需要关注的“持仓超过首档额度”。未知值和缓存回退不能触发超额提醒。

同一关注状态持续时不重复生成提醒；状态恢复后再次进入关注状态，才生成新的关注事件。红点表示仍有未读关注事件：即使状态在用户查看前已经恢复，原红点也会保留到用户打开时间轴。打开某产品的时间轴后，服务端将该产品所有未读关注事件的 `read_at` 写入 D1；刷新后不重现已读红点，但以后再次恶化仍可生成新提醒。普通变化记录不参与红点已读状态。

实现与回归测试：`lib/product-change-events.ts`、`app/components/product-history.tsx`、`tests/product-change-events.test.mjs`。

资格要求只作说明，不使用复选框、不自动推断用户资格。到期后统一显示“已于 mm/dd 到期”，保留原 APR，用户自行管理。定期/限时产品缺买入日会阻止收益计算，不阻止比较 APR 和已知额度。

| 顶部指标 | 计算范围 |
|---|---|
| 总持仓 | 活跃目录内已知金额 |
| 组合有效 APR、预计每日收益 | 产品完整且持仓大于零；APR 按实际阶梯占用加权 |
| 最佳首档 APR | 活跃目录内首档 APR 和适用金额范围已知的产品；单一利率按覆盖全部金额处理。只比较首档 APR，不要求买入日。已确认不可申购、不合资格或不在申购窗口内的产品不计入；资格待确认仍可比较，保留资格提示。有限额度还要求持仓已知 |
| 高息剩余额度 | 汇总 APR ≥ 6% 的适用金额范围，包含定期；已确认不可申购、不合资格或不在申购窗口内的产品不计入，资格待确认可计入。有限额度要求持仓已知；单一 APR 没有档位边界或明确开放档按无上限处理；多档产品若末端无法确定，则不计入未确认部分 |
| 超出首档 | 首档上限及持仓已知 |

多档产品的 `max: null` 只有在适配器已确认“最后一档上限字段未返回”或平台明确给出开放上限后，才标记为不限额；其他 `max: null` 仍是未知。最后一档上限未返回时，有可读产品总上限就用它补齐；没有产品总上限就按最后一档不限额处理。字段存在但不可解析、档位缺失或不连续时，提示“首档额度未获取”或“阶梯额度未获取”，并暂停依赖未确认范围的计算。产品/账号申购上限仍独立判定，不能从利率覆盖范围推出。

### 产品移除与 API 断开

- 两种 API 移除操作范围不同，不可互换。单个 API 产品仅在持仓明确为零时可从列表移除；该操作只隐藏一条产品，保留凭证、产品记录、持仓/设置数据和变更历史。持仓为正数或未知时拒绝移除；之后重新检测到持仓时会再次显示。
- 移除某个平台的 API 配置，会清除凭证和当前同步快照，并将该账户所有 API 产品从活动目录归档。不会删除已保存的持仓、持仓明细、产品资料或变更历史；重新配置并成功同步后，产品目录可恢复。
- 移除单个手动产品，会删除该手动产品及其持仓、持仓明细和人工设置，但保留产品变更记录。

移除产品先修改编辑草稿，确认保存后生效；取消编辑会恢复原状。移除 API 配置另有确认步骤，说明其影响范围。

## 同步与时间

计划任务由 Worker 配置 `SCHEDULED_SYNC_ENABLED` 控制；仓库默认配置为 `false`，暂停每日 07:00 的队列更新。重新设为 `true` 并部署即可恢复。暂停期间页面不显示计划更新时间，也不会等待计划任务；数据加载完成且同步成功时顶部显示“当前数据截至 {时间}，每日首次打开自动更新。”当天首次打开已登录页面仍刷新一次，成功失败均计次，按账号、上海日期在服务器记录，多设备共用。主动点击手动刷新保留原冷却设置，不执行分钟级重试；每日打开刷新不占用手动按钮的冷却。

计划任务启用时，上海时间每天 07:00 投递更新。失败或部分成功时，等 3 分钟进行最后一次尝试（实际完成时间包含请求耗时与投递延迟）。

Cron 只向 `SYNC_QUEUE` 投递每个用户的任务，队列每次仅消费一条（`max_batch_size: 1`），最多重试一次。不能在同一次 Worker 调用中等待后重复同步，也不能把多个用户合并消费，否则会共享外部请求额度。消费并发为 1；队列任务只含用户标识与计划时刻，不含密钥或资产数据。

重试开始前若本时段已有提交的数据或已记录自动任务最终失败，则跳过；超过下一计划时段的旧任务也跳过。`sync_snapshots` 保存结果，`refresh_control` 原子记录每日打开刷新和账号级运行锁，避免浏览器、队列互相覆盖。页面遇到后台重试窗口先等待，结束后再尝试当天首次打开刷新；等待不会提前占用当天次数。首次无缓存也走同一入口，不另发首次同步。单个用户一次同步仍受运行平台限制。

| 同步结果 | 保存与提示 |
|---|---|
| 重试中 | 中间候选不提交；显示“正在更新”，已有目录和持仓保持可见 |
| 首次重试中、无缓存 | 显示“数据正在更新中，请稍候。”与骨架屏，不提前显示最终失败 |
| 完全成功 | 目录和缓存同批提交，清除失败提示 |
| 最后一次部分成功 | 提交部分结果，按平台/币种/接口提示具体失败 |
| 最后一次全部失败 | 保留缓存，统一提示“产品和持仓数据更新失败” |
| 手动刷新冷却 | 不请求交易所，不清除上一轮失败或缓存提示；顶部按钮保留“手动刷新”并置灰，不显示倒计时；右上角菜单显示“冷却至 HH:mm” |
| 浏览器读取失败 | 本轮流程结束仍缺必要数据时，统一显示服务器读取失败，不推断交易所失败 |

每次打开或浏览器刷新，个人保存数据和交易所缓存各读取一次，再通过每日刷新入口判断当天是否需要更新交易所。初次读取失败不取消当天应执行的刷新，也不重复读取个人数据；交易所刷新不能补回个人保存数据。读取与每日刷新连续显示更新中，不在两步之间闪过下次更新时间。读缓存不占每日次数、不请求交易所、不回写持仓。

进行中：无论是否已读到历史数据，统一使用中性色加粗显示“数据正在更新中，请稍候。”；不使用独立的 warning 橙褐色。已有历史数据时继续保留产品、持仓和缓存说明，但顶部不显示旧时间。新账号、尚未读到或任一部分读取失败时使用骨架屏，不单独展示另一部分的时间。到 07:00 的计划窗口、后台进行中及页面等待使用相同提示；仍保留 15 分钟超时保护，正常情况下最终尝试结束即结束后台提示。

流程结束：个人保存数据仍读取失败，或交易所缓存及后续结果始终读取失败，优先显示暗红色加粗的“服务器读取失败，数据无法显示，请刷新页面。”，不带时间或交易所失败提醒，不提供重试按钮。统计保留六项布局，数值为“—”；整表使用同文案空状态，禁止编辑，不能把空状态写回服务器。数据完整读到后显示数据时间；计划任务启用时同时显示下次计划更新时间，暂停时显示“每日首次打开自动更新”。API 同步失败时显示具体失败原因；部分失败、全部失败但有缓存、全部失败且无缓存均在提示卡右侧提供小号绿色实心“手动刷新”按钮，左侧时钟与文案作为整体垂直居中、顶部对齐，图标与文案第一行等高，文案可换行。按钮受手动刷新冷却限制；读缓存成功不能清除上次同步失败。确认交易所全失败且没有缓存，不是页面读取失败，仍保留已读到的手动产品。

### 顶部提示状态表

| 情况 | 触发条件 | 顶部完整文案 | 样式与动作 |
|---|---|---|---|
| 首次读取 / 任意自动刷新进行中 | 个人数据读取、每日首次打开刷新或其他自动刷新尚未结束 | 数据正在更新中，请稍候。 | 中性色；有缓存时保留页面内容，无缓存时显示骨架屏；不显示旧时间或刷新按钮 |
| 同步成功，定时任务暂停 | 数据读取完整，`SCHEDULED_SYNC_ENABLED=false` | 当前数据截至 {时间}，每日首次打开自动更新。 | 数据时间使用次级文字色；不显示操作按钮 |
| 同步成功，定时任务启用 | 数据读取完整，定时任务正常 | 当前数据截至 {时间}，预计 {时间} 自动更新。 | 数据时间使用次级文字色；不显示操作按钮 |
| 查询成功，但 API 必需字段缺失 | 请求与分页完整，某产品的 APR、额度、期限或有持仓时的买入日期缺失 | 当前数据截至 {时间}，{平台} · {产品} · {具体字段}未获取 | 沿用顶部危险色提示和手动刷新按钮；请求状态仍为成功，不写成“部分返回”或“API 暂不可用” |
| API 部分失败 | 有成功结果，但至少一项 API 未完整返回 | 当前数据截至 {时间}，{具体未返回项} | 左侧显示时钟、次级色数据时间和红色失败原因；右侧显示小号绿色实心“手动刷新”按钮 |
| API 全部失败，有缓存 | 本轮 API 全失败，但有可展示的上次成功数据 | 当前数据截至 {时间}，本次产品和持仓数据更新失败 | 保留上次成功时间；左侧失败原因用危险色并允许换行；右侧显示小号绿色实心“手动刷新”按钮，遵守手动刷新冷却 |
| API 全部失败，无缓存 | 本轮 API 全失败，且没有上次成功数据 | 暂无成功数据，{失败原因} | 不伪造数据时间；左侧失败原因用危险色并允许换行；右侧显示小号绿色实心“手动刷新”按钮 |
| 服务器读取失败 | 流程结束后，个人保存数据或交易所缓存仍无法读取 | 服务器读取失败，数据无法显示，请刷新页面。 | 危险色并加粗；优先于 API 状态；不显示数据时间、交易所失败原因或手动刷新按钮 |
| 已启用的定时任务自身失败 | 定时任务已启用，但计划时段的自动更新仍未完成 | 当前数据截至 {时间}，{计划时间} 定时更新失败，下次更新将重试。 | 时间使用次级色，任务失败用危险色；仅定时任务启用时可能出现，与 API 同步失败区分 |

状态优先级：服务器读取失败优先于 API 状态；任一 API 同步失败或必需字段未获取时隐藏“每日首次打开自动更新”或预计更新时间；刷新进行中统一显示进行中提示。API 字段未获取可与请求失败原因同时列出，但不改变请求状态。API 部分失败、全部失败或必需字段未获取时显示右侧按钮；页面读取失败、计划任务自身失败和刷新进行中不显示。手动刷新按钮冷却期间不可点击，仍保留相同布局与危险原因文案。提示条的时钟图标和文案首行顶部对齐、等高；图标与文案整体在提示条内容区垂直居中。

手动刷新冷却：设置项为“无”或“30 分钟”，未保存个人偏好时默认 30 分钟。服务器按当前登录用户记录手动请求开始时间；请求即使失败也会开始冷却，同一用户的多设备共用。每日首次打开和定时刷新不占用此冷却。冷却中，顶部失败提示里的按钮仍显示“手动刷新”但置灰，不展示时间；右上角操作菜单显示固定的可重试时刻“冷却至 HH:mm”，不是逐秒倒数。

页面每分钟轮询，编辑和首次加载流程中暂停；每日刷新被后台任务延后时继续申请，完成后只读缓存，跨天保持打开也不再刷。个人保存数据失败时，仅完成尚待执行的每日刷新，不继续普通轮询或回写持仓。手动刷新保留个人数据未加载时的重新读取分支。

本地预览可用 `/private?syncScenario=personal-error`、`product-read-error`、`both-read-error` 分别模拟个人、交易所缓存、两份数据读取失败；这些参数不会在生产环境启用。
截图回归可在本地预览使用 `previewAt=2026-10-06T10:00:00.000Z` 固定模拟数据的时间，并在浏览器测试中固定页面时钟；生产环境不接受这一模拟入口。

**时间按数据自身来源保留：**产品使用原始 `rate.fetchedAt`；持仓连续失败继承原 `holdingFallbacks`，不能替换成整轮 `updatedAt`。缓存提示不根据错误文案猜测。页面读缓存不写持仓表；同步事务在服务器直接保存新刷新实际取得的 API 持仓（包括零），浏览器不再另发一次持仓保存请求。平台整体成功/失败不能替代单条持仓的新旧判断。API 产品的移除和金额保存以可信同步快照为准，客户端空值不能清零。

## 验证方式

运行 `npm test` 执行离线测试，运行 `npm run check` 同时检查代码、类型和构建。`npm run test:e2e` 使用本地预览和 Chromium 检查页面加载、加载骨架、币种切换、编辑弹窗键盘操作、变更时间轴、模拟保存/移除和窄屏溢出。保存与移除测试拦截 PUT，只接受 `preview=1` 并返回模拟响应，不写入 D1；全部测试不连接线上账号或生产 D1。离线测试覆盖同步状态、身份映射、历史分页和关键数据边界。
