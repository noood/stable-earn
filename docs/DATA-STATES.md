# 数据状态与展示规则

本文是产品、持仓和缓存状态的统一判断依据。界面文案可以调整，但不能改变以下数据含义。

## 核心原则

1. 产品信息与持仓信息独立判断；一方成功不代表另一方成功。
2. 接口明确返回的 `0.00` 是真实零持仓；完整余额快照中缺少的产品也按零处理；稀疏持仓接口未返回的产品显示“未获取”。
3. 正常计划缓存不提示异常；只有更新失败并沿用旧数据时才显示缓存时间。
4. APR、额度、必要期限或买入日缺失时，产品不参与收益和额度计算。
5. 最终 APR 由程序维护的是 API 产品，由用户维护的是人工产品。API 暂时失败不会改变产品类型。
6. 当前账号可以移除人工产品，以及需要资格确认、固定期限或活动期限的产品；没有这些条件的 API 活期产品不可移除。移除不会影响交易所账户或 API 配置。
7. 未登录页只使用固定演示数据，不请求交易所接口，也不写入私人存储。

代码分别使用 `productDataMode`、`holdingDataMode` 和 `rateCoverage` 表达产品来源、持仓来源及 APR 完整度，三者不能互相推断。活期、定期、限时是产品属性，不是第四种数据来源；来源只有 API 或人工。

API 同步结果还保留 `productId`（产品目录中的内部稳定 ID）、可选的 `externalProductId`（平台原始 ID）、`identityKey`（内部比较值）和产品身份指纹。适配器统一生成这些字段；外部 ID 可用时会参与身份比较，期限、资格和阶梯结构变化也会记录在指纹中。APR 或额度的普通波动不会创建新产品。

身份模型不再区分 `canonical`、`external`、`manual` 类型；`productDataMode` 只说明数据来源，`identityKey` 负责统一身份比较，人工产品直接使用自己的 `productId`。

同步时会按账号维护产品目录。首次遇到的身份沿用对应的初始目录行；身份 ID、资格、期限或阶梯结构变化时创建新的内部 `productId`，旧行标记为归档并保留历史。再次出现旧身份时可恢复该行，不会与新身份合并。

## 产品信息

| 状态 | 查看态 | 编辑态 | 计算 |
|---|---|---|---|
| API 完整返回 | 展示 APR 与额度 | 只读，并显示“来自 API” | 参与 |
| API 更新失败，有缓存 | 产品列显示“产品信息沿用……的缓存数据”；持仓列显示“持仓沿用……的缓存数据” | 同样只读 | 参与 |
| 无可用产品数据（从未成功或失败无缓存） | APR、额度等对应字段显示“待获取”，补充“产品信息不完整，不参与收益计算” | 只读，并显示“来自 API”和“产品信息不完整，不参与收益计算” | 不参与 |
| API 只返回基础或最高 APR | 展示已知值和待确认项，补充“产品信息不完整，不参与收益计算” | 只读，并显示“来自 API”和“产品信息不完整，不参与收益计算” | 不参与；最高 APR 可作顶部参考 |
| 人工信息完整 | 展示 APR、额度及期限 | 显示对应输入项 | 参与 |
| 人工信息缺失 | 展示具体“待填写”项，并补充“产品信息不完整，不参与收益计算” | 显示对应输入项和“产品信息不完整，不参与收益计算” | 不参与 |

定期、限时或奖励期产品有持仓时还需要买入日。产品列负责说明具体缺失字段，并在查看态和编辑态统一提示“产品信息不完整，不参与收益计算”；没有持仓时该提示使用中性色。持仓列只描述持仓状态：编辑态已有输入框时不重复显示持仓结果，产品信息完整时才补充进度和额度信息；如果持仓本身是缓存，即使产品信息不完整也保留“持仓沿用……的缓存数据”注释。有效 APR、收益和额度指标还必须同时满足“产品完整、持仓已知、持仓大于 0”。

编辑态的“删除产品”是当前账号的移除操作：人工产品、需要资格确认的 API 产品，以及固定/活动期限产品可移除；没有这些条件的 API 活期产品仍属于产品目录，不提供删除。移除后会同步清理该账号对应的持仓和人工覆盖值。

`rateCoverage` 的含义：

- `complete`：信息完整，可以计算；
- `base_only`：只有基础 APR 或缺少首档结构；
- `max_only`：只有最高 APR，可作参考但不计算；
- `unavailable`：尚无 APR。

## UI 统一规则

- 产品列只显示 APR/额度/期限、来源和产品完整性；持仓列只显示金额、额度进度、缓存或同步原因。
- 正常状态不加说明；缓存使用 warning 色；产品不完整且无持仓使用中性色；失败使用明确原因，不叠加多条同义文案。
- 查看态的未知持仓显示“持仓未获取”加一条原因；编辑态输入框显示“未获取”，只保留同一条原因。
- 产品不完整时持仓列不显示进度条；编辑态不重复金额。产品完整时，查看态显示金额、进度和额度，编辑态由输入框显示金额，下面只保留进度和额度；不限额产品编辑态不再重复摘要。

## 持仓信息

| 状态 | 查看态 | 编辑态 | 计算 |
|---|---|---|---|
| API 返回正数 | 展示持仓、额度进度和有效 APR | 只读，并显示“来自 API” | 产品完整时参与 |
| API 明确返回零 | 展示 `0.00` | 只读，并显示“来自 API” | 无收益 |
| API 更新失败，有缓存 | 展示缓存值和缓存时间 | 只读 | 产品完整时参与 |
| API 未配置 | 产品满足查看态筛选时显示“持仓未获取”，并提示“未配置 API；配置后可同步持仓” | 只读，并显示同样提示 | 不参与 |
| API 已配置但同步失败 | 产品仍在列表时显示“持仓未获取”，并提示“API 同步失败，持仓未获取” | 只读，并显示同样提示 | 不参与 |
| API 已同步但未返回该产品 | 显示“持仓未获取”，并提示“接口未返回该产品持仓” | 只读，并显示同样提示 | 不参与 |
| 人工持仓 | 展示已保存金额 | 显示输入框 | 产品完整时参与 |

`holdingSourceIds` 表示曾经获得明确结果的产品，`holdingUpdates` 保存本轮成功金额，`holdingFallbacks` 保存本轮失败时沿用的缓存时间。产品不在 `holdingSourceIds` 中时，缺失值不能解释为零。

查看态原本就会在产品已因持仓或机会条件进入列表、但持仓结果未知时显示“持仓未获取”；编辑态的输入框已经显示“未获取”，下方只保留原因提示，不重复显示“持仓未获取”。本次只补充原因，不改变该行是否进入列表。对于 `holdingDataMode` 为 `api` 的产品，按同步状态分别提示“未配置 API；配置后可同步持仓”、“API 同步失败，持仓未获取”或“接口未返回该产品持仓”。有缓存时产品列和持仓列分别标明对应的缓存数据；人工持仓不显示 API 配置提示。API 配置入口仅在编辑态显示，统一打开配置面板。

产品下架不能仅凭一次接口缺失判断：同步失败或接口暂时省略时保留现有行；只有适配器明确确认产品不可用后，才将目录行归档并停止展示，历史数据仍保留。

## 列表与指标

- 未登录查看态仅展示固定 USDT 样板；USDC、USDGO、BTC 显示空状态。演示修改刷新后恢复。
- 新用户的产品目录按账号建立，不预置所有交易所或纯人工产品。公开 API 成功确认的产品、账户 API 同步发现的产品，以及用户主动添加的人工产品才会进入当前账号目录。
- 已登录查看态展示真实持仓、APR 严格高于 4% 的活期及 7 天内定期机会，以及用户添加的人工产品。
- 已登录编辑态展示当前账号已同步的 API 产品和用户添加的人工产品；没有 key 的账户 API 产品不会凭空出现。
- API 同步发现的新身份会自动加入编辑态目录；适配器同时提供目录所需的平台、地区和资产信息时，完全陌生的 `canonicalProductId` 也会自动建行。被用户移除的产品按目录 ID 保存，不会误删后来出现的新身份。
- API 配置是登录用户的常规入口；编辑态的“配置 API”只打开配置面板，不代表当前行一定缺少 key。
- 有效 APR、组合 APR、每日收益和额度指标只使用产品完整且持仓已知的数据。
- 没有可展示产品时只显示简短空状态。

## 验收重点

- 产品和持仓分别覆盖成功、失败有缓存、失败无缓存；
- 明确零持仓与未获取不混淆；
- API 字段只读，人工字段可编辑；
- 任一必要字段缺失时不进入计算；
- 未登录页不访问交易所接口或私人数据。
