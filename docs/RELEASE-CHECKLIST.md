# 发布前检查清单

发布审查统一按四个方面记录结果。部署和数据库迁移不是独立的第五类：按其影响分别纳入“代码与功能”或“开源安全”，并把需要用户在 Cloudflare 控制台执行的步骤单独标为操作项。
下面的复选框是每次发布复用的模板；本次结果记在文末，不勾选模板项不表示已通过。

## 1. 代码与功能

- [ ] `npm run check` 通过：lint、类型检查、离线测试和生产构建。
- [ ] `npm run test:e2e` 通过；按本次改动补充页面关键路径、加载/错误状态、弹窗与键盘交互测试。
- [ ] 检查本次差异和工作区未提交改动，确认没有误带用户改动、调试路由、测试凭证或生成文件。
- [ ] 检查数据边界、权限校验、错误处理、兼容行为及日志是否泄露个人数据。
- [ ] 若包含 D1 迁移：逐条检查 SQL、执行前查询、重复执行/回滚策略和新旧代码兼容性；明确标记由操作者远程执行的 SQL，并在执行后核对结果。未经明确授权，不对生产 D1 写入。
- [ ] 若涉及部署配置：核对变量和 Worker Secret 的“名称/是否配置”，不得读取或输出 Secret 值；确认部署目标与所需迁移顺序。

## 2. UI 与样式

- [ ] 检查桌面宽度与 375px 窄屏：页面无意外横向溢出，宽表格在自身容器内滚动。
- [ ] 检查首次加载、后台刷新、空状态、失败状态和内容较长状态；对齐、间距、字号、颜色与现有 token/设计规范一致。
- [ ] 检查查看/编辑/取消/确认等关键状态，以及时间轴、红点、弹窗定位和关闭行为。
- [ ] 键盘操作可达，焦点进入/限制/恢复正确；检查 Escape、Tab 顺序和可访问名称。
- [ ] 有视觉敏感改动时保存桌面/窄屏截图并人工比对；没有基线的截图检查不称为“视觉回归通过”。

## 3. 开源安全

- [ ] 运行 `npm audit` 并单独运行 `npm audit --omit=dev`；区分生产依赖和开发工具链告警，核对依赖路径与可达性。
- [ ] 对每项告警记录修复、接受风险或待调查的决定及复查触发条件；不能以“开发依赖”直接等同于“无风险”。
- [ ] 检查认证、私有路由、凭证加密、Secret 管理、跨站请求防护和敏感日志；确认没有提交真实密钥或用户数据。
- [ ] 检查仓库漏洞报告渠道与部署者安全要求是否真实、可操作；不声称尚未确认的 GitHub 仓库设置已开启。

### 暂缓的开发依赖告警

完整审计报告 9 项 high 告警，根因是开发依赖链中的 `braces@3.0.3`（GHSA-vfj7-8cjw-p6xm，经 `fast-glob`、`micromatch` 等引入），不是 9 个互不相关的生产漏洞。生产依赖审计为 0 项。已知风险是特定深度嵌套 brace/glob 模式可能导致栈耗尽和拒绝服务；开发工具/构建流程若处理不可信模式时尤其需要关注。它不等于已证明线上请求可触发，但也不能据此声称安全无风险。

`npm audit fix --force` 当前建议将 `eslint-config-next` 降到 14.2.35，属于可能破坏 Next.js 16 工具链的 breaking change，本次没有执行。暂时接受告警的条件：保留在发布风险记录中；每次发布重跑审计；出现安全公告升级、依赖链变化、生产依赖引入该包或构建处理不可信输入时重新评估。若审计无法联网，应明确标为“未完成”，不能记为通过。
