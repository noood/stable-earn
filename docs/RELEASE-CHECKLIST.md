# 发布前检查清单

本文件是每次发布前复用的检查标准，不记录日常开发进度或逐次审查结果。每次准备部署时，按下列四方面检查当前代码；未检查的项目明确标为“未验证”，不能推断为通过。

检查中发现的阻断问题、未验证项和用户需执行的远程操作，直接在对话中说明；不要将逐次审查结果或测试流水追加到本清单或要求用户粘贴到 GitHub。未经明确授权，不部署、不修改 GitHub/Cloudflare 远程设置、不写入生产 D1，也不读取或输出 Secret 值。

## 1. 代码与功能

- [ ] `npm run check` 通过：lint、类型检查、离线测试和生产构建。
- [ ] `npm run test:e2e` 通过；按本次改动补充页面关键路径、加载/错误状态、弹窗与键盘交互测试。无法运行时标为“未验证”并说明原因。
- [ ] 检查本次差异和未提交工作区，确认没有误带用户改动、调试路由、测试凭证或生成文件。
- [ ] 检查数据边界、权限校验、错误处理、兼容行为及日志是否泄露个人数据。
- [ ] 若包含 D1 迁移：检查 SQL、执行前条件、重复执行/回滚策略和新旧代码兼容性；明确列出由操作者远程执行的步骤。未经明确授权，不对生产 D1 写入。
- [ ] 若涉及部署配置：核对变量和 Worker Secret 的名称/是否配置，不读取 Secret 值；确认部署目标与迁移顺序。

## 2. UI 与样式

- [ ] 检查桌面宽度与 375px 窄屏：页面无意外横向溢出，宽表格在自身容器内滚动。
- [ ] 检查首次加载、后台刷新、空状态、失败状态和长内容；对齐、间距、字号、颜色符合设计规范。
- [ ] 检查查看/编辑/取消/确认等关键状态，以及时间轴、红点、弹窗定位和关闭行为。
- [ ] 检查键盘可达性、焦点进入/限制/恢复、Escape、Tab 顺序和可访问名称。
- [ ] 视觉敏感改动保存桌面/窄屏截图并人工比对；没有基线时不声称通过像素级视觉回归。

## 3. 开源安全

- [ ] 运行 `npm run audit:security`（并行检查完整依赖与生产依赖）；区分生产依赖与开发工具链告警，核对依赖路径及可达性。
- [ ] 对审计发现的每项告警判断处置方式（修复、接受风险或待调查）及复查条件；不能仅以“开发依赖”判为无风险。
- [ ] 检查认证、私有路由、凭证加密、Secret 管理、跨站请求防护和敏感日志；确认没有提交真实密钥或用户数据。
- [ ] 检查漏洞报告渠道和部署者安全要求是否真实可用；没有重新确认的 GitHub 仓库设置不得写成已启用。

## 4. 开源文档

- [ ] README 的功能、运行/测试/部署说明与当前实现一致；命令可以照文档执行。
- [ ] 根目录 `LICENSE`、README 许可说明和包元数据一致；检查[第三方许可证盘点](THIRD-PARTY-LICENSES.md)及发布产物中的许可证/归属义务。
- [ ] `SECURITY.md` 给出真实可用的私下报告途径、处理预期和部署者责任。
- [ ] 数据规则、身份/迁移说明和设计规范没有过时行为、临时排障记录或与代码相矛盾的结论。
- [ ] 检查新增文件、第三方资产和引用内容的许可证/来源及所需归属声明。

## 每次部署前如何使用

收到发布前审查请求后，按本清单检查当前差异，并向用户说明阻断问题和未验证项。用户准备发布时，另提供简短的 GitHub 发布说明。除非用户明确要求，本仓库不新增逐次审查报告，也不要求用户把审查清单粘贴到 GitHub。
