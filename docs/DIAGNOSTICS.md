# 诊断入口与一次性探针

本文是项目诊断能力的单一索引。它区分页面启动诊断、平台能力检查器和专项只读探针，避免把它们误认为同一种工具或稳定的公开 API。

## 使用边界

- `/private` 页面返回静态页面外壳，不在页面路由本身验证应用登录；用户数据 API 会验证应用身份。部署环境可再用 Cloudflare Access 保护页面和 API。当前线上 Access 路径规则为 `/private*`，覆盖 `/private` 入口及其子路径；自托管时应确认规则也匹配不带尾斜杠的入口。
- 下表的专项探针会使用当前用户已保存的交易所只读凭证调用交易所接口。不要为了探针创建带交易/提现权限的密钥。
- 专项探针不写入产品、持仓、缓存或历史数据。`bitget-usdgo` 会写入脱敏的应用诊断日志；能力检查器只在检测到平台限流时记录用户冷却时间。
- 探针是维护/排查入口，不承诺为长期稳定 API；路径会随对应代码版本部署而存在。不要向用户文档或外部服务宣传这些路由。
- 手动探针可能触发交易所限流。每次排查只运行所需的最窄范围，不要为了单个币种运行全平台检查。

## 入口总览

| 类型 | 入口 | 作用与范围 | 调用和副作用 |
| --- | --- | --- | --- |
| 页面启动诊断 | 私有页面 URL 加 `?diagnostics=1`；已有查询参数时用 `&diagnostics=1` | 测量页面启动、账户读取与每日刷新，展示浏览器及服务端计时、资源和可用 D1 指标；含义与限制见[页面启动指标](#页面启动指标与限制)。不提供上游响应正文或交易所子请求明细 | 仅诊断模式返回状态与计时；浏览器内临时显示，不保存或上报面板内容，不改变刷新和页面状态 |
| 平台能力检查器 | “数据源设置 → API 检测”；`POST /private/api/diagnostics/platform-capabilities` | 检查代码已知的平台 API 能力，覆盖产品/APR 与持仓；不是未知接口发现器 | 只读调用已配置账号；限流时会保存该用户的冷却时间；报告不写入产品或持仓 |
| Bitget 产品专项探针 | `GET` 或 `POST /private/api/diagnostics/bitget-products` | 默认检查 Bitget 产品资料；可用 `?asset=USDC&productId=...` 指定单产品容量检查 | 只读产品接口，不读取持仓；当前 Worker 实例内每用户 30 秒冷却，不保证跨实例或实例重启后仍生效 |
| Binance 定期产品专项探针 | `GET` 或 `POST /private/api/diagnostics/binance-locked-products` | 检查已配置 Binance Global/Bahrain 账号的定期产品 APR、额度和申购状态；不会请求持仓 | 每个已配置账号最多一次产品列表请求；当前 Worker 实例内每用户 30 秒冷却，不保证跨实例或实例重启后仍生效 |
| Binance 活期档位专项探针 | `GET` 或 `POST /private/api/diagnostics/binance-usdc-tiers?asset=USDC` | 检查 USDC 活期 APR 档位；`asset` 支持 USDC、USDT、BTC，省略时默认为 USDC | 每个已配置 Binance 账号最多一次公开产品列表请求；不读持仓、不写产品/缓存/历史；当前 Worker 实例内每用户 30 秒冷却，不保证跨实例或实例重启后仍生效 |
| Bitget USDGO 专项探针 | `POST /private/api/diagnostics/bitget-usdgo` | 一次读取 Bitget USDGO 产品与持仓接口能力，返回脱敏状态/计数 | 不写 D1 业务数据；会记录脱敏应用诊断字段；没有跨请求冷却 |

专项 API 路由既接受已登录的同站 GET，也接受经过同源校验的 POST；`bitget-usdgo` 仅提供 POST。所有路由都不接受匿名调用。

## 如何选择

1. 页面打不开、启动卡住或 UI 显示初始化错误：先用页面启动诊断；它只能说明浏览器到应用接口的状态，不能证明上游交易所实际返回了什么。
2. 要确认项目内已知 API 能力或多平台同步状态：从设置页运行平台能力检查器。它范围较广，只有确实需要跨平台盘点时才运行。
3. 已把问题缩小到某平台/币种/产品时：选择上表对应的专项探针，避免重复运行通用检查器。
4. 要判断线上上游响应内容：以应用明确记录且脱敏的诊断字段为证据；Worker 请求日志中的 URL、HTTP 状态或 `outcome=ok` 本身不能说明产品数据字段是否正确。

私人产品路由的每日/手动刷新会记录脱敏的 `refresh_requested`、`refresh_skipped`、`refresh_dispatched` 事件，并与 `sync_started` / `sync_finished` 使用同一 `runId`；每日刷新另外记录 `daily_refresh_committed`。诊断面板中的“每日刷新请求”来自本次接口返回的处理状态，不再把普通缓存轮询称为每日刷新。当天已有最终结果时，接口只返回“今日刷新尝试已处理，本次只读取缓存”；这不能证明本次请求重新同步了数据。跳过事件说明是运行锁、后台计划重试窗口、当天已提交或手动冷却；完成事件只记录上海日期和成功、部分成功或已保存失败，不记录持仓金额、产品行、凭证或 API 响应。若看到请求/派发记录但没有完成记录，只能说明这次流程没有留下最终提交证据；日志本身不能确定 Worker 被取消的具体原因。

## 页面启动指标与限制

线上页面异常时，登录后可在私有页面 URL 后添加 `?diagnostics=1`（已有查询参数时改用 `&diagnostics=1`）。启动诊断分别记录 HTML 请求/首字节/下载结束、客户端模块执行与挂载、仪表盘模块实际加载起止、首次渲染与 DOM 提交、初始化任务和下一帧的时点，并记录导航类型及启动期间是否进入后台；有后台标记的样本不能直接代表正常前台加载速度。

“骨架屏移除（DOM提交）”记录指标和表格退出骨架的首次提交，并说明当时展示保存数据、无成功数据终态还是读取失败界面；它不是浏览器精确像素绘制事件。“顶部更新提示结束（DOM提交）”单独记录更新提示退出的时点。“首次打开流程结束”记录个人数据、缓存及每日刷新请求这段流程全部结束，不能用它代替缓存首次显示或骨架移除的时间。有可用历史数据时，骨架可以先结束，顶部仍连续显示更新中。

每日刷新请求会显示已执行并保存完整/部分结果、失败、中断、等待已有刷新/计划窗口，或今天已有刷新尝试因而本次只读缓存；首次缓存已确认完成时显示“无需请求：服务端确认今日尝试已完成”，不伪造 HTTP 状态或请求耗时。普通缓存轮询单独标为“产品缓存轮询”。HTTP 200 不代表同步执行或数据变化。持仓和产品接口显示浏览器总耗时、从导航开始的请求起止时点及服务端总耗时；两者差值包含网络传输、浏览器调度和响应解析，不能单独当作网络时间。持仓 GET 将批量读取及其结果转换标为“批量读取个人数据快照”；缓存 GET 将合并查询标为“读取缓存、设置与刷新状态”，与到期检查的计时可以重叠；每日入口继续细分登录校验、数据库准备、刷新设置、运行锁、缓存读取、当日记录检查、手动产品到期检查和变更记录读取。实际执行同步时只记录整段同步耗时，不细分交易所请求。分段起止从该接口开始计，不能直接把重叠分段相加；“其余处理”是总时间扣除已计时区间并集的剩余时间。

诊断仅输出固定步骤名、数值和处理状态，不显示响应正文、账户数据或密钥，不改变同步判定与页面状态。不带参数时面板隐藏，接口不返回诊断结果或计时头。面板不保存或上报诊断内容，检查后移除参数即可。

历史诊断在同一次产品响应内记录“历史摘要调用总耗时”；旧客户端记录“读取旧版历史缓存”及是否命中，未命中时另记“重建旧版历史缓存”“历史合并去重排序”。批量重建不伪造最近历史与未读提醒各自独立的调用往返时间。调用总耗时包含 D1 调用等待、往返及结果接收，不等于 SQL 执行耗时；D1 提供时另列实际结果中的 `timings.sql_duration_ms`、`duration`、返回条数、扫描行数及 `total_attempts`。摘要返回条数是产品数，不是事件总数。D1 的独立 SQL 耗时只反映末次执行尝试；存在自动重试时，不能用调用总耗时减去末次 SQL 耗时直接推断网络耗时。未提供的 SQL 耗时和尝试次数明确显示缺失，不填 0ms 或默认一次；`duration` 单独标为 D1 duration，不冒充缺失的独立 SQL 指标。

登录诊断保留原有 JWT 签名、签发方、受众和有效期验证及公钥缓存规则，仅观察解析签名公钥的耗时、解析前缓存/请求状态，以及本请求实际发起的公钥网络请求至响应头的耗时。网络至响应头不包含后续正文读取和公钥解析；它们属于公钥解析总耗时。等待其他请求的公钥结果时，不把其他请求的网络计时复制过来。服务端诊断上下文按请求隔离，不写入运行日志。

浏览器资源诊断只展示同源关键脚本/样式的固定分类标签、导航后的请求起止、可用的首字节等待/下载时间和传输/压缩正文大小，不输出资源 URL 或查询参数。零传输量不单独证明命中缓存；下载区间不等于脚本执行区间。Long Tasks API 支持时，缓冲观察 ≥50ms 的主线程长任务，在首次打开流程结束后冻结启动窗口的数量、区间和累计时间；任务跨越窗口时截断区间，最长展示 5 条。不支持该 API 时明确显示“不支持”，不能当作零阻塞。诊断自身有少量观察与面板更新开销，长任务也不能单独归因于某个脚本；这些数据用于定位，不是完整 CPU 性能剖析。

脚本角色通过当次构建生成的启动资源映射识别，与私人页预加载共用；映射只含固定角色和公开脚本地址，文件名改为纯 hash 后仍可匹配。它随静态页面传入，不增加浏览器映射请求。面板的入口、启动阶段、冻结窗口及隐私边界不变。构建实现见 `scripts/startup-assets.mjs`，运行时类型及标签见 `lib/startup-assets.ts`。
