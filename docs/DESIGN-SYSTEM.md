# 界面设计规范

## 统一基础

- 复用 `app/globals.css` 的颜色、字号、间距、圆角和尺寸变量；表格列宽/间距由 `.product-table-*` 控制，不按产品单独覆盖。
- 普通信息用中性色；同步不完整、沿用缓存、到期、超出首档和其他需要注意的状态统一用 danger（暗红色）；不再使用独立的 warning 橙褐色。服务器读取失败、保存失败与删除/移除等谨慎操作也使用同一 danger 色。同类状态在统计卡片、表格和弹窗中保持同色，不新增颜色。
- 通用按钮、徽标、指标、单元格、持仓摘要和弹窗使用 `app/components/ui.tsx`；独立功能使用独立组件。只在结构和职责稳定复用时抽象。
- 文字按钮统一使用 `ActionButton` 的 `text` 变体：品牌色、600 字重、无下划线；悬停时切换为品牌悬停色。内联的次级文字动作使用共享的 `.button-text-inline-action` 修饰类，以 `--type-caption` 和对应行高呈现，去掉额外内边距并与正文基线对齐，不降低字重。菜单项、分段选择、日历日期格等专用控件沿用各自交互样式。
- 实心/描边按钮使用统一的两档尺寸；`ActionButton` 默认常规档，小号通过 `size="small"` 使用。常规档为 14px/20px、40px 高、水平内边距 16px、圆角 10px；小号为 12px/16px、32px 高、水平内边距 12px、圆角 8px，两档字重均为 600。高度、内边距和小号圆角由 `--button-*` token 定义，常规圆角复用 `--radius-control`；按钮变体只负责颜色，不改变尺寸。文字按钮、图标按钮和分段选择控件是独立控件，不套用这两档的外观；分段控件需要与相邻常规按钮等高时，使用常规按钮高度 token。
- 顶部 API 失败或产品必需 API 字段未获取提示的恢复动作用 `ActionButton` 的小号实心主按钮，和公开页“登录查看我的数据”按钮保持一致；警示文案留在左侧并可换行，按钮固定在右侧。
- 顶部状态提示中，时钟图标与文案的第一行顶部对齐且使用相同行高；图标与文案作为一个整体在提示条内容区垂直居中，文案可换行，右侧操作按钮独立居中。

## 基础 Token

`app/globals.css` 是运行时代码的唯一来源；本节是 token 的使用约定，新增样式先复用现有变量，不直接写新的布局数值。

同值、同用途的颜色只保留一个来源：按钮上的白色引用 `--surface`，进度轨道、只读输入框和普通浅灰提示共用 `--surface-muted`。成功图标使用 `--status-success`；danger 仍用于错误与需关注状态。资产品牌色属于交易所标识，不与应用品牌色合并。小图标按钮共用 `--compact-icon-size`，API 提示框共用 `api-feedback-panel` 的内边距。
同尺寸的账户徽标与设置加载占位共用 `--account-badge-size`；圆形节点与进度轨道共用 `--radius-pill`；页面最大宽度共用 `--page-max-width`。审核重复数值时按用途合并，不把表格列宽、不同大小的状态徽标、图标内部笔画或为文字基线微调的数值强行归并。
交互焦点环共用 `--focus-ring-width` 与 `--focus`；小号圆角使用 `--radius-sm`，不另写近似的圆角数值。极细分隔线使用 `--hairline`；状态点描边、控件边框和时间轴线条可以保留 1px，以保证这些细节在视觉上清晰。

### 文字颜色

| Token | 值 | 默认用途 |
|---|---|---|
| `--text-primary` | `#18201d` | 正文、标题、主要数值 |
| `--text-secondary` | `#68736d` | 说明、元信息和次要文字 |
| `--text-muted` | `var(--text-secondary)` | 兼容旧名称，与 secondary 共用颜色，不是独立灰阶 |
| `--text-subtle` | `#929b96` | 禁用内容及装饰性弱提示，不用于重要信息 |

`--brand` 与 `--danger-text` 分别用于品牌操作和危险/错误状态。次级文字色在白底对比度约 4.93:1；更浅的 `--text-subtle` 只用于信息不重要或禁用的场景。

### 间距梯度

| Token | 值 | 默认用途 |
|---|---:|---|
| `--space-1` | 4px | 图标与文字、极小的内部留白 |
| `--space-2` | 8px | 紧凑控件内部间距、短列表间距 |
| `--space-3` | 12px | 组件内部间距、提示卡内边距、时间轴事件间距 |
| `--space-4` | 16px | 卡片与卡片之间、普通组件间距 |
| `--space-5` | 20px | 卡片内部主要 padding |
| `--space-6` | 24px | 较宽的组件内部留白、指标分隔区域 |
| `--space-8` | 32px | 页面级大间距 |
| `--space-control` | 10px | 控件内 padding，以及指标/输入等组件的紧凑内部节奏 |

布局间距只使用 `4 / 8 / 12 / 16 / 20 / 24 / 32px`。`10px` 不作为通用梯度，只用于控件或组件内部的紧凑节奏；如果新场景只是普通内容留白，应归入 8px 或 12px。表格专用的 `--table-cell-x`、`--table-middle-x` 等只服务表格列对齐，不扩展为通用间距 token。1px 边线、图标尺寸和圆角属于其他 token 系列，不计入间距梯度。

## 状态与文案

- 产品列解释产品信息；持仓列解释持仓。主状态、原因、来源不要重复。
- 缓存必须说明对象与时间；关键原因和时间允许换行，不用省略号截断。
- 正常 API 数据在查看态不额外标来源，编辑态只读框显示“来自 API”；有缺失或缓存说明时优先显示说明。
- 产品字段缺失时保留已知持仓；首档边界已知就显示首档额度和剩余额度，即使买入日期或后续档位待补。首档边界未知时隐藏其进度和剩余额度；后续档位未知时不声称超出首档的部分按某个 APR 计息。编辑框下不重复孤立金额。未知持仓不按零置灰。
- 资格未知只显示“待确认”，不增加勾选操作。具体规则见 [数据规则](DATA-STATES.md)。
- 首次加载使用骨架屏；已有数据后台刷新时保留内容。保存失败提示跨表格全宽、紧接标题区，并保留草稿。
- 顶部提示的各状态、文案、优先级、颜色与操作见[数据状态表](DATA-STATES.md#顶部提示状态表)。
- 流程结束仍缺必要数据，优先显示 `text-danger font-semibold` 的“服务器读取失败，数据无法显示，请刷新页面。”；不带时间或交易所提醒，统计显示“—”，整表使用同文案空状态，禁止编辑。完整读到数据后再展示交易所同步结果。
- 删除用统一确认弹窗，取消为次按钮，删除为危险主按钮；保存草稿后才持久化。

## 布局与交互

- 卡片之间使用 `16px`，卡片内部使用 `20px`；其余场景按上面的间距 token 约定选择，不新增页面级硬编码间距。
- 状态切换应避免不必要的高度/位置跳动，不要求所有内容绝对等高。标题区信息相近时保持稳定；真实新增内容可以自然增高。
- 查看态和编辑态按钮组使用独立节点，避免复用上一按钮的颜色过渡。
- 移动端资产 tab 单行横滑，不纵向溢出；宽表格在自己的容器内横滑，不能撑宽整个页面。
- Footer 与表格间距紧凑，两侧均衡留白；GitHub 品牌入口有无障碍名称。
- 更多菜单：私人页先“手动刷新”，再“API 设置”；公开页保留 API 设置入口，登录后打开设置，不出现空菜单。
- API 设置用一句话说明同步能力。可配置平台在前，人工维护平台接在下面，无单独分组和无效按钮。

## 验收

至少检查桌面和窄屏、查看/编辑/取消、零/未知/缓存持仓、字段不完整、同步中/部分失败/全部失败、保存失败及公开页菜单。测试入口见 [数据规则与测试](DATA-STATES.md#验证方式)。
视觉回归使用固定本地模拟时间和 Chromium 截图基线：公开页、私人页四币种及编辑态按桌面/375px 整页比较；设置弹窗的顶部/底部、变更记录气泡和加载/空/同步状态分别截图。基线先经人工检查，之后的像素差异还要人工判断，不能只因测试通过就认定设计正确；真实账户和其他浏览器未纳入这些截图基线。
