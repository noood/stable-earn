# 界面设计规范

## 统一基础

- 复用 `app/globals.css` 的颜色、字号、间距、圆角和尺寸变量；表格列宽/间距由 `.product-table-*` 控制，不按产品单独覆盖。
- 普通信息用中性色；更新中、同步不完整、沿用缓存、到期和超出首档用 warning（橙褐色）；服务器读取失败、保存失败与删除/移除等谨慎操作用 danger（暗红色）。同类状态在统计卡片、表格和弹窗中保持同色，不新增颜色。
- 通用按钮、徽标、指标、单元格、持仓摘要和弹窗使用 `app/components/ui.tsx`；独立功能使用独立组件。只在结构和职责稳定复用时抽象。

## 状态与文案

- 产品列解释产品信息；持仓列解释持仓。主状态、原因、来源不要重复。
- 缓存必须说明对象与时间；关键原因和时间允许换行，不用省略号截断。
- 正常 API 数据在查看态不额外标来源，编辑态只读框显示“来自 API”；有缺失或缓存说明时优先显示说明。
- 产品不完整时保留已知持仓，隐藏依赖产品完整性的进度/额度；编辑框下不重复孤立金额。未知持仓不按零置灰。
- 资格未知只显示“待确认”，不增加勾选操作。具体规则见 [数据规则](DATA-STATES.md)。
- 首次加载使用骨架屏；已有数据后台刷新时保留内容。保存失败提示跨表格全宽、紧接标题区，并保留草稿。
- 顶部更新提示使用 `text-warning font-semibold`：历史数据完整读到且有时间时显示“当前数据截至……。正在更新中，请稍候。”，否则显示“数据正在更新中，请稍候。”。读取与每日刷新连续衔接，中间不显示下次更新时间。
- 流程结束仍缺必要数据，优先显示 `text-danger font-semibold` 的“服务器读取失败，数据无法显示，请刷新页面。”；不带时间或交易所提醒，统计显示“—”，整表使用同文案空状态，禁止编辑。完整读到数据后再展示交易所同步结果。
- 删除用统一确认弹窗，取消为次按钮，删除为危险主按钮；保存草稿后才持久化。

## 布局与交互

- 状态切换应避免不必要的高度/位置跳动，不要求所有内容绝对等高。标题区信息相近时保持稳定；真实新增内容可以自然增高。
- 查看态和编辑态按钮组使用独立节点，避免复用上一按钮的颜色过渡。
- 移动端资产 tab 单行横滑，不纵向溢出；宽表格在自己的容器内横滑，不能撑宽整个页面。
- Footer 与表格间距紧凑，两侧均衡留白；GitHub 品牌入口有无障碍名称。
- 更多菜单：私人页先“手动刷新”，再“API 设置”；公开页保留 API 设置入口，登录后打开设置，不出现空菜单。
- API 设置用一句话说明同步能力。可配置平台在前，人工维护平台接在下面，无单独分组和无效按钮。

## 验收

至少检查桌面和窄屏、查看/编辑/取消、零/未知/缓存持仓、字段不完整、同步中/部分失败/全部失败、保存失败及公开页菜单。测试入口见 [数据规则与测试](DATA-STATES.md#验证方式)。
