# 界面设计规范

## 统一基础

- 复用 `app/globals.css` 的颜色、字号、间距、圆角和尺寸变量；表格列宽/间距由 `.product-table-*` 控制，不按产品单独覆盖。
- 普通信息用中性色；同步不完整、沿用缓存、到期、超出首档和其他需要注意的状态统一用 danger（暗红色）；不再使用独立的 warning 橙褐色。服务器读取失败、保存失败与删除/移除等谨慎操作也使用同一 danger 色。同类状态在统计卡片、表格和弹窗中保持同色，不新增颜色。
- 通用按钮、徽标、指标、单元格、持仓摘要和弹窗使用 `app/components/ui.tsx`；独立功能使用独立组件。只在结构和职责稳定复用时抽象。说明浮层与变更记录共用锚点定位、视口避让和触发器离屏关闭逻辑，面板外框复用 `anchored-popover`；密钥及公开钱包地址共用设置字段组件，仅输入类型与保存语义不同。
- 文字按钮统一使用 `ActionButton` 的 `text` 变体：品牌色、600 字重、无下划线；悬停时切换为品牌悬停色。内联的次级文字动作使用共享的 `.button-text-inline-action` 修饰类，以 `--type-caption` 和对应行高呈现，去掉额外内边距并与正文基线对齐，不降低字重。菜单项、分段选择、日历日期格等专用控件沿用各自交互样式。
- 平台展示名统一由 `lib/platform-display.ts` 提供，账户身份与 API 能力定义仍各自独立。列表、设置与检测报告复用名称；MEXC 检测报告合并 PH/UK 展示，但不合并两个账户身份。
- 产品列表与数据源设置的平台图标共用 `AccountBadge`，读取账户的本地 `logo`；Bybit EU 使用独立标识，其余同品牌地区共用图标。继续复用 `--account-badge-size`、`--radius-card`，边框使用 `--hairline` 和 `--badge-border`，透明区域使用 `--surface`，不另维护字母徽标或品牌底色。
- 实心/描边按钮使用统一的两档尺寸；`ActionButton` 默认常规档，小号通过 `size="small"` 使用。常规档为 14px/20px、40px 高、水平内边距 16px、圆角 10px；小号为 12px/16px、32px 高、水平内边距 12px、圆角 8px，两档字重均为 600。高度、内边距和小号圆角由 `--button-*` token 定义，常规圆角复用 `--radius-control`；按钮变体只负责颜色，不改变尺寸。文字按钮、图标按钮和分段选择控件是独立控件，不套用这两档的外观；分段控件需要与相邻常规按钮等高时，使用常规按钮高度 token。
- 数据源设置的交易所「添加」、钱包「添加」和「检测 API」使用 40px 常规次按钮。「检测 API」宽 96px，检测、完成及冷却时保持相同尺寸。
- 私人页顶部的 API 失败或必需字段缺失提示使用小号实心「手动刷新」按钮，位于警示文案右侧。公开页演示提示中的「登录」使用行内文字按钮，与正文基线对齐。
- 顶部提示条使用透明背景，无边框。正常显示数据时间、启动骨架、加载和更新过程中都使用静态时钟。模块加载失败、服务器读取失败、API 同步失败、必需字段缺失或定时更新失败显示铃铛。未登录时的演示提示也使用铃铛，文字和读屏播报沿用普通提示。时间和进行中提示用常规字重（400），失败原因与缺失字段用危险色和半粗体（600）。图标与整段文案垂直居中，间距 8px，文案可换行。右侧操作按钮垂直居中，与文案区间距 24px。

## 基础 Token

`app/globals.css` 是运行时代码的唯一来源；本节是 token 的使用约定，新增样式先复用现有变量，不直接写新的布局数值。

同值、同用途的颜色只保留一个来源：按钮上的白色引用 `--surface`，进度轨道、只读输入框和普通浅灰提示共用 `--surface-muted`，零持仓行复用 `--surface-subtle`。成功图标使用 `--status-success`；danger 仍用于错误与需关注状态。资产品牌色属于交易所标识，不与应用品牌色合并。数据源行图标按钮使用 `--compact-icon-size`，变更历史按钮使用 32px 小按钮尺寸。
同尺寸的账户徽标与设置加载占位共用 `--account-badge-size`；圆形节点与进度轨道共用 `--radius-pill`；页面最大宽度共用 `--page-max-width`。审核重复数值时按用途合并，不把表格列宽、不同大小的状态徽标、图标内部笔画或为文字基线微调的数值强行归并。
交互焦点环共用 `--focus-ring-width` 与 `--focus`；小号圆角使用 `--radius-sm`，不另写近似的圆角数值。极细分隔线使用 `--hairline`；状态点描边、控件边框和时间轴线条可以保留 1px，以保证这些细节在视觉上清晰。

### 文字颜色

| Token | 值 | 默认用途 |
|---|---|---|
| `--text-primary` | `#18201d` | 正文、标题、主要数值 |
| `--text-secondary` | `#65706a` | 说明、元信息和次要文字，`text-secondary` 与 `text-muted` 样式类共用此颜色 |
| `--text-subtle` | `#929b96` | 禁用内容及装饰性弱提示，不用于重要信息 |

`--brand` 与 `--danger-text` 分别用于品牌操作和危险/错误状态。次级文字色在白底对比度约 5.15:1，在 `--surface-muted` 浅灰底约 4.53:1；更浅的 `--text-subtle` 只用于信息不重要或禁用的场景。

### 间距梯度

| Token | 值 | 默认用途 |
|---|---:|---|
| `--space-1` | 4px | 图标与文字、极小的内部留白 |
| `--space-2` | 8px | 紧凑控件内部间距、短列表间距 |
| `--space-3` | 12px | 组件内部间距、提示卡内边距、时间轴事件间距 |
| `--space-4` | 16px | 卡片与卡片之间、普通组件间距 |
| `--space-5` | 20px | 卡片内部主要 padding |
| `--space-6` | 24px | 较宽的组件内部留白、指标分隔区域 |
| `--space-8` | 32px | 页面级大间距 |
| `--space-control` | 10px | 控件内 padding，以及指标/输入等组件的紧凑内部节奏 |

布局间距只使用 `4 / 8 / 12 / 16 / 20 / 24 / 32px`。`10px` 不作为通用梯度，只用于控件或组件内部的紧凑节奏；如果新场景只是普通内容留白，应归入 8px 或 12px。表格横向内边距使用 `--table-cell-x`，指向 32px 间距。1px 边线、图标尺寸和圆角属于其他 token 系列，不计入间距梯度。

### 投影与动效

| Token | 参数 | 用途 |
|---|---|---|
| `--shadow-card-editing` | 下偏移 4px、模糊 8px、不透明度 8% | 编辑中的持仓卡片 |
| `--shadow-dialog` | 下偏移 12px、模糊 20px、不透明度 12% | 弹窗和浮层 |

- `--motion-quick`（160ms）用于按钮、图标和零持仓行的颜色或透明度过渡。数据源设置的遮罩淡入和面板入场也沿用这个时长，使用 `ease-out`。面板从最终位置下方 4px 上移并淡入。
- `--motion-editing-duration`（200ms）用于编辑按钮组淡入和卡片投影过渡，使用 `ease`。开启系统「减少动态效果」时，弹窗和持仓编辑直接显示目标状态。

## 状态与文案

- 设置里的保存结果、读取错误和检测反馈复用 `FeedbackPanel` 的颜色、内边距和辅助技术播报。普通反馈默认用 `status`，错误默认用 `alert`；限流等待提示沿用 danger 外观，用 `status` 播报。
- 持仓表的平台名用半粗体（600）。产品信息列的 APR 数字标签和红色异常提示用半粗体（600）。其余字段、编辑控件和「APR 未获取」「APR 待填写」标签用常规字重（400）。持仓摘要中，持仓金额用半粗体，斜杠及后面的额度说明用常规字重。产品列解释产品信息；持仓列解释持仓。主状态、原因、来源不要重复。
- 产品收益标签以展示的两位小数 APR 分档：低于 6% 使用现有浅灰背景和正文色；6% 至不足 9% 沿用现有标签浅绿，9% 至不足 12% 和 12% 以上使用由标签浅绿与品牌边框绿混合的渐深背景。6% 至不足 12% 的数字使用品牌色，12% 以上使用正文色，提高可读性。已知 APR 即使额度等字段不完整也按数值分色；APR 未获取或待填写沿用次级灰色，具体缺失说明独立展示。此分色仅用于呈现，不改变机会筛选、收益计算或变更提醒的原始数值规则。
- 字段缺失文案按来源区分“未获取”（API、只读）与“待填写”（人工、可编辑），不使用笼统的产品信息报错；日期推算、计算参与与缓存边界统一见 [数据规则](DATA-STATES.md#api-结果状态与持仓产品降级规则)，这里不另维护一套判断。
- 缓存必须说明对象与时间；关键原因和时间允许换行，不用省略号截断。
- 正常 API 数据在查看态不额外标来源，编辑态只读框显示“API 同步”；有缺失或缓存说明时优先显示说明。
- 产品收益区的额度名称与范围以空格连接，不使用中间点，例如“首档 0.00–300.00”“首档 不限额”；定期产品沿用“申购额度”名称，例如“申购额度 不限额”。查看态和编辑态共用此规则；持仓列同样保留额度名称，例如“持仓 {金额} / 首档 不限额”。
- 产品信息中的短字段名（如“买入日期”“锁定期限”）保持单行，右侧的值按可用宽度换行。空间不足时，买入日期和到期说明优先分行。
- BGW 默认显示“Bitget Wallet / 活期理财”，编辑态复用产品类型、APR、首档额度和只读持仓控件。奖励说明图标只在编辑态的 APR 标签旁显示；人工填写的来源时间不常驻展示。配置、额度与计算规则统一见[钱包数据规则](DATA-STATES.md#bitget-wallet--morph)。
- 产品字段缺失时保留已知持仓；首档边界已知就显示首档额度和剩余额度，即使买入日期或后续档位待补。首档边界未知时隐藏其进度和剩余额度；后续档位未知时不声称超出首档的部分按某个 APR 计息。编辑框下不重复孤立金额。未知持仓不按零置灰。
- 未知类型在产品名下方用危险色显示“产品类型未知”，不在收益区重复报错；已知 APR、额度和持仓照常展示。人工类型选择复用同一控件，只列活期、定期、限时活期；开放条件及期限规则统一见[产品类型与人工设置](DATA-STATES.md#产品类型与人工设置)。
- 资格未知只显示“待确认”，不增加勾选操作。具体规则见 [数据规则](DATA-STATES.md)。
- 私人页启动外框与正式页共用导航、页脚、表格工具栏、列宽和滚动容器。品牌、表头和已知的指标标签直接显示，指标数值使用骨架，状态提示显示静态时钟和文案骨架。已知币种的持仓标题直接显示，未知币种用骨架；目录说明和产品行用骨架。工具栏统一控制「编辑持仓」的尺寸。宽度在 359px 及以下时，加载、失败和正常状态都使用 12px 字号和 12px 水平内边距。加载时按钮禁用，导航不做骨架。账户数据逐块替换骨架，不切换另一套布局。
- 总览按每一排最高的标题对齐该排数值。标题全部为一行时只占一行，平台名换行时仅撑高所在排。正常、加载和失败状态共用此布局。
- 总持仓、超出首档只显示标题和数值；最佳首档 APR 在标题后显示对应的平台。组合有效 APR、预计每日收益和高息剩余额度使用带虚线的普通文字与箭头光标。标题的说明气泡仅在悬停时打开，并提供读屏说明。
- 模块加载失败时保留外框，指标说明显示“加载失败”，目录说明显示“持仓信息加载失败”；账户读取失败也沿用相同的外框和空态组件。两阶段的完整文案、数据可用性及禁用范围以[启动与读取规则](DATA-STATES.md#私人页启动与账户数据读取)和[顶部状态表](DATA-STATES.md#顶部提示状态表)为准。
- 两阶段失败的本地入口为 `/private?moduleScenario=error` 和 `/private?syncScenario=both-read-error`，约 1 秒后进入对应失败状态，生产环境不启用；移除参数后返回普通预览。其他测试入口见[开发指南](../CONTRIBUTING.md#本地预览)。保存失败提示跨表格全宽、紧接标题区，并保留草稿。
- 顶部提示的各状态、文案、优先级、颜色与操作见[数据状态表](DATA-STATES.md#顶部提示状态表)。
- 流程结束仍缺必要数据，顶部优先用危险色半粗体显示“服务器读取失败，数据无法显示，请刷新页面。”；不带时间或交易所提醒，统计显示“—”，整表使用同文案空状态，禁止编辑。完整读到数据后再展示交易所同步结果。
- 删除用统一确认弹窗，取消为次按钮，删除为危险主按钮；保存草稿后才持久化。

## 布局与交互

- 页面和顶部导航使用相同的浅灰底色。在所有屏幕宽度下，公开页和私人页的导航底部到提示条均留 8px。提示条上下各留 8px，左右各留 4px。总览和持仓卡片使用白底和细边框。提示条、总览和持仓之间相距 16px。普通卡片内边距为 20px，指标卡上下 24px、左右 20px。
- 页面容器居中，最大宽度为 1500px。小于 1024px 时两侧各留 20px。桌面两侧各留 40–100px，先给表格留出 1000px 和卡片边框，再增大留白。导航、提示条、指标和表格共用这套边距。
- 表头、数据行和骨架共用列宽，各列左右内边距和行分割线两端的缩进均为 32px。有效 APR 列默认总宽 120px，内容区宽 56px。标题和数值右对齐，实际显示内容超过 56px 时整列按需加宽。变更列固定为 104px，图标居中。桌面平台列占 24%，产品信息和持仓均分剩余空间。小于 1024px 时平台列占 22%，产品信息列占 28.5%，余量分给持仓列。表格最小宽度为 1000px，空间不足时在容器内横向滚动。
- 状态切换应避免不必要的高度/位置跳动，不要求所有内容绝对等高。标题区信息相近时保持稳定；真实新增内容可以自然增高。
- 人工首档额度在原输入框右侧放置下拉按钮，菜单仅列“限额”“不限额”；不限额时框内显示“不限额”并隐藏币种单位，切回限额后待填写。聚焦数字输入或下拉按钮都由整个 `.manual-field-control:focus-within` 呈现焦点环，内部不另画焦点框；复用现有菜单定位、键盘与关闭交互。额度箭头与日期图标共用 16px 尺寸及控件右侧内边距，箭头左侧用 12px 高短竖线隔开，限额与不限额状态都保留。共用下拉菜单按最长选项、固定勾选位及内边距决定宽度，并限制在视口内；菜单普通选项用 `--text-primary`，选中项通过字重和背景区分，勾选标记复用共享的线性 SVG `CheckIcon`，不使用字体对号。API 同步的额度保持只读。
- 编辑字段区按实际可渲染的输入项决定是否出现；没有任何输入项时，不生成外层分隔线、内边距或空白容器。外层显示条件与各输入项的条件使用同一判定，不因只读信息仍存在而渲染空编辑区；此规则适用于全部产品，不按平台、币种或产品 ID 特判。
- 变更记录气泡按内容调整宽度，上限为 320px，窄屏时随视口收窄。长标题和变更前后的值在气泡内换行。空状态、首次加载和首次加载失败共用骨架屏对应的最小内容高度；“暂无变更记录”和重试文案在这块区域水平、垂直居中。有历史记录时由列表自然撑开，不强行固定高度。
- 查看态和编辑态按钮组使用独立节点，避免复用上一按钮的颜色过渡。
- 数据源设置中的更多菜单支持 Escape 关闭并把焦点交还给菜单按钮。继续按 Escape 可关闭设置并回到打开弹窗的入口。Tab 在弹窗内的可用控件间循环。
- 导航内容相对下方卡片的左右边缘各内收 4px，品牌字标使用 18px 半粗体。640px 起采用 72px 高的单行导航，币种标签的点击区高 56px。较窄屏幕使用双行导航，标签在第二行横滑，点击区高 44px。直接打开币种链接、返回页面或调整窗口时，币种栏按需横移，让当前标签完整可见。选中或悬停的标签均显示 40px 高的浅灰色圆角背景，复用 `--surface-muted` 与 `--radius-control`，图标左侧与币名右侧各留 12px。当前币种使用深绿文字，键盘焦点显示焦点环。
- 页脚与表格间距紧凑。页脚和顶部提示条的内容相对卡片边缘均内收 4px，GitHub 品牌入口有无障碍名称。
- 导航的“更多操作”使用三个直径 3px 的实心圆点，图标为 20px，点击区为 40px 方形。默认透明、无描边，悬停及菜单展开时使用与币种标签相同的 `--surface-muted` 浅灰底和正文色。下拉菜单项左侧留 12px、右侧留 8px，上下各留 10px，单行悬停背景与币种标签灰底同高。账号信息和分割线与菜单项文字左对齐。私人页菜单先显示“手动刷新”，再显示“数据源设置”。页面初始化读取期间刷新按钮禁用并显示“手动刷新”，用户手动刷新进行中显示“正在刷新…”。公开页保留数据源设置入口，登录后打开设置。
- 数据源设置包含“配置 API”和“钱包地址”。钱包区标题下说明“通过钱包地址同步链上理财持仓。”；API 检测说明“检查交易所接口是否可用、能获取哪些数据，并生成检测报告。”，只读及报告隐私边界保留在功能文档中。交易所可配置平台在前，人工维护平台接在下面；列表行上下各留 16px，行间分割线左右各缩进 16px，与内容边缘对齐。配置状态标签使用常规字重（400），平台行标题与说明间距为 4px。钱包区复用相同的平台徽标、平台名、配置状态、添加按钮及已配置后的操作菜单，副标题为“Morph 链”，说明钱包所在网络；输入框标为“钱包地址”，不额外常驻填写说明。公开地址使用“保存”，交易所密钥仍使用“加密保存”。

## 验收

至少检查桌面和窄屏、查看/编辑/取消、零/未知/缓存持仓、字段不完整、同步中/部分失败/全部失败、保存失败及公开页菜单。测试入口见 [开发指南](../CONTRIBUTING.md#本地预览)。
视觉回归使用固定本地模拟时间和 Chromium 截图基线：公开页、私人页四币种及编辑态按桌面/375px 整页比较；设置弹窗的顶部/底部、变更记录气泡和加载/空/同步状态分别截图。基线先经人工检查，之后的像素差异还要人工判断，不能只因测试通过就认定设计正确；真实账户和其他浏览器未纳入这些截图基线。
