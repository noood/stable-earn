# 界面设计规范

界面以信息清楚、层级安静和跨状态一致为目标。新增样式前优先复用现有变量与组件。

## 基础规则

- 颜色、字号、间距、圆角和控件尺寸统一由 `app/globals.css` 中的变量管理。
- 正常信息使用中性色；缓存和需注意状态使用 warning；保存失败等错误使用 danger。
- 表格列宽和单元格间距由 `.product-table-*` 统一控制，不在单个产品中覆盖。
- 说明文字保持弱化，不为普通信息额外增加背景、阴影或强调色。
- 移动端允许内容换行，不通过扩大固定宽度解决文案长度。

## 组件边界

通用按钮、徽标、指标、表格单元格、持仓摘要和弹窗结构位于 `app/components/ui.tsx`。API 设置等独立功能使用单独组件；只服务于产品表格的展示组件保留在仪表盘模块中。

相同结构出现多次时再抽象。组件应表达一个稳定职责，避免只为减少少量代码而增加跳转层级。

## 状态表达

- 正常 API 数据在查看态不额外标注来源；编辑态显示“来自 API”并保持只读。
- 缓存或缺失提示可以代替来源说明。
- 信息不完整时展示具体原因，但所有原因共用同一计算排除规则。
- 风险颜色只用于真正需要注意的状态；正常期限进度不使用警示色。
- 空状态只显示简短文字，不使用装饰图标。
