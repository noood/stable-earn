# 界面设计规范

界面以信息清楚、层级安静和跨状态一致为目标。新增样式前优先复用现有变量与组件。

## 基础规则

- 颜色、字号、间距、圆角和控件尺寸统一由 `app/globals.css` 中的变量管理。
- 正常信息使用中性色；缓存和需注意状态使用 warning；保存失败等错误使用 danger。
- 表格列宽和单元格间距由 `.product-table-*` 统一控制，不在单个产品中覆盖。
- 产品信息列适当加宽以容纳期限与资格说明，有效 APR 列相应收窄；中间两列通过更大的内部间距保持内容紧凑，首列位置和表格两侧留白不刻意向页面边缘移动。
- 说明文字保持弱化，不为普通信息额外增加背景、阴影或强调色。
- 移动端允许内容换行，不通过扩大固定宽度解决文案长度。
- 移动端资产 tab 保持单行横向滚动，不换成多行，也不产生纵向溢出；桌面端保持原有横向排列。
- Footer 左侧放免责声明，右侧放官方 GitHub lockup；两侧保留均衡内边距，GitHub 入口只使用品牌标识并提供无障碍名称。
- Footer 与产品表格保持紧凑但清楚的间距，不再额外叠加大段上下留白。

## 组件边界

通用按钮、徽标、指标、表格单元格、持仓摘要和弹窗结构位于 `app/components/ui.tsx`。API 设置等独立功能使用单独组件；只服务于产品表格的展示组件保留在仪表盘模块中。

相同结构出现多次时再抽象。组件应表达一个稳定职责，避免只为减少少量代码而增加跳转层级。

## 状态表达

- 正常 API 数据在查看态不额外标注来源；编辑态显示“来自 API”并保持只读。
- 产品列只负责产品信息，持仓列只负责持仓信息；不要在两列重复同一原因。
- 缓存提示必须注明是产品缓存还是持仓缓存；缺失提示只保留一个明确原因。
- 主状态与原因不得重复同一信息。例如输入框或主文案已显示“持仓未获取”时，辅助文案只写“API 同步失败”。
- 信息不完整时查看态和编辑态显示具体原因，例如“买入日待填写，不参与收益计算”；无持仓时使用中性色。
- 产品信息不完整时不显示进度条或剩余额度。完整产品在查看态和编辑态显示完整持仓摘要，编辑态额外保留持仓输入框。
- 资格只在产品列展示：未知时使用简短的“待确认”，不使用复选框，也不在持仓列重复。
- 风险颜色只用于真正需要注意的状态；正常期限进度不使用警示色。
- 空状态只显示简短文字，不使用装饰图标。
- 首次读取私人数据时，顶部提示、指标和产品表使用尺寸稳定的 skeleton；已有内容的后台刷新不替换整页内容。
- 状态切换以视觉稳定为原则：信息和操作没有实质变化时，不应产生不必要的高度或位置跳动。产品表标题区当前为查看态和编辑态预留稳定空间；内容确实需要更多空间时可以自然增高，不为绝对等高而截断或挤压信息。
- 表格级保存失败提示紧接标题区并横跨整个表格；不与表头重叠，也不使用卡片内的左右缩进。
- 删除产品使用统一二次确认弹窗；取消为次按钮，删除为危险主按钮。删除先作用于编辑草稿，保存后才持久化。
- 查看态与编辑态的按钮组使用独立节点，避免切换时沿用上一按钮的颜色过渡。
- API 设置的平台列表用一句话说明每个平台的同步方式；可配置平台提供 Key 入口，完全依赖人工录入的平台接在列表底部并标记“手动维护”，不再增加单独分组或无效按钮。产品筛选规则不在弹窗中重复解释。
- 公开页右上角“更多”保留 API 设置入口；点击后先完成登录，再在私人页自动打开设置，不显示空菜单或未登录可提交的凭据表单。
