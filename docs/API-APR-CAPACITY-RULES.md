# APR 与额度规则

适用范围：本项目接入的活期、定期 Earn 产品。本文件只维护字段解析与已确认的额度语义；目录、字段缓存、状态展示和计算参与规则见[数据状态规则](DATA-STATES.md)。逐平台、地区、币种已核实的产品回包记录在[平台能力总表的“最近结果”列](PLATFORM-CAPABILITIES.md)，不在这里重复维护产品明细。

## 统一规则

| API 返回情况 | 利率怎么用 | 额度怎么定 | 代码处理 |
|---|---|---|---|
| Binance 活期有实时基础 APR 和奖励档 | 奖励档内：基础 APR + 该档奖励 APR；奖励档以外：回到基础 APR | 奖励档边界只限定奖励利率；没有另报总申购上限时，基础 APR 继续适用后续金额 | 生成“最终 APR 档位”，诊断 JSON 同时保留基础 APR、奖励 APR、最终 APR |
| Binance 活期有基础 APR、没有奖励档 | 直接用基础 APR | 按单一 APR 处理；未返回金额上限时按不限额 | 单一利率完整，不标“梯度未获取” |
| 其他平台返回单一 APR/APY | 直接用该利率，不与别的字段或产品相加 | 未返回 APR 适用金额上限时按不限额；另有明确的产品累计申购上限时，按该上限限制。单笔申购上限不当作累计额度 | 空梯度本身不算缺失；坏的/不可解析的上限不算不限额 |
| 其他平台返回多档 APR/APY | 每档直接使用对应值，不加顶层 APR | 每档按自己的金额范围；API 给了产品总上限但没写最后一档终点时，用总上限补齐最后一档；没有产品总上限且最后一档没有返回上限时，最后一档按不限额处理 | 要求每档利率可读、从 0 起、档间连续且无重叠；补出来的终点在 JSON 中标明来源 |
| 多档最后一档返回明确的 `-1` 上限 | 使用该档 API 返回的利率 | 该档按不限额处理 | 只接受识别出的 `-1` 或“最后一档上限字段未返回”；字段有值但不可解析，不当作不限额 |
| 多档最后一档有有限上限，且没有更大的总申购上限 | 使用返回的每档利率 | 只覆盖到最后一档上限，不把利率外推到更大金额 | 有限范围可以是完整梯度，不要求末档一定无限 |
| 多档最后一档有有限上限，但产品总申购上限更大或为 `-1` | 保留已返回的各档利率 | 末档以上的额度没有对应利率，不能当成已覆盖 | 标“阶梯结构未获取”，不计算整笔持仓收益；只有 API 返回覆盖该范围的档位，或最后一档上限字段未返回且可按上面规则解释为开放档时才恢复 |
| 多档缺档、边界不可解析/不连续，且总上限无法补齐 | 仅保留能确认的字段，不猜缺失部分利率 | 已知额度可以展示，不能据此声称整款方案完整 | 产品资料标部分；整款产品排除收益与机会指标，详见数据状态规则 |
| 产品列表成功但目标币没有产品行 | 不填 0 APR | 不虚构额度 | 标“没有返回该币种产品”；这和“字段未返回”或“请求失败”分开 |
| 产品总上限与产品池剩余量同时存在 | 利率仍由 APR/档位决定 | 申购上限限制账户/产品累计可申购量；产品池余量是另一项限制，不能互相代替，也不能当持仓 | 检查 JSON 分字段记录；不读取持仓时不计算账户剩余可买量 |

## 额度字段怎么区分

- **利率档位边界**：决定金额落在哪个 APR/APY 档。比如 Bybit Global USDT 的 0–200 档是 7.3%，之后是 2.3%。
- **独立产品申购上限**：不属于某个利率档位的边界，而是单独限制整款产品最多能申购多少。Bybit 使用 `maxStakeAmount`；Binance 定期使用 `quota.totalPersonalQuota`。例如第一档 0–200、第二档开放，产品累计申购上限为 1,000：第二档的利率覆盖范围和整款产品的申购限制分别判断，不能因第二档开放就认定可无限申购。Bybit 定期还会给 `minStakeAmount`，它是最低申购量。
- **当前还可申购多少**：如果该上限是账户累计上限，还要用上限减去同一产品当前已持仓；只有上限字段本身不够，API 检查 JSON 不计算这个值。
- **产品池剩余量**：Bybit 的 `remainingPoolAmount`，表示页面单独显示的产品池余额，不是个人持仓，也不代替 `maxStakeAmount`。
- **Bitget**：产品列表的 `apyList` 记录单利率或各 APY 档；`singleMaxAmount` 只限制一笔申购，不代表账户累计额度，也不作为高息额度边界。订阅详情的 `remainingAmount` 不用于本次 APR/梯度判断，也不当持仓或梯度额度。

## “完整”与“没有返回”的判定

1. 请求成功并把分页读完，只能说明列表读取完整；还要逐产品检查身份、利率形状和档位边界。产品身份可识别但 APR/额度坏值属于单产品资料不完整，不自动把请求标为部分返回；必要身份、分页或查询范围不完整才影响请求完整性，详见[数据状态规则](DATA-STATES.md#api-结果状态与持仓产品降级规则)。
2. 有 APR/APY 的单利率产品不要求多档。按本项目确认的规则，没有金额上限时按不限额处理；如果明确上限字段已返回，则按该值限制。
3. 多档产品必须逐档解析。只解析到一档不代表完整；但 API 明确声明 `single` 的产品只有一档是正常结果。
4. 多档若最后一档上限字段未返回，且有可读的产品总申购上限，就用总上限补齐；没有产品总上限时，最后一档按不限额处理。在已确认的平台档位规则中，末档边界原始值 `null` 也表示“未提供该档上限”，按同一规则补齐或开放；这项例外只适用于末档边界，不适用于中间档边界或独立产品申购上限。独立上限（例如 `maxStakeAmount`）存在但为 `null`、空字符串或不可解析值时是不可读，不是不限额。坏字符串（例如 `300abc`）不能使用未返回上限的规则。
5. “没有返回该币种产品”是完整列表里没有产品行；“额度字段未返回”是产品行在但某个字段不存在；“额度不可解析”是字段在但值坏了。这三者不能互相替代。

## 当前代码落实

- Binance 活期把基础 APR 与奖励 APR 分开保存，生成的奖励档使用相加后的最终 APR；奖励档外按基础 APR。无奖励档时按单一基础 APR。
- Bybit 活期和定期校验整段档位是否覆盖产品总上限；最后一档上限字段未返回时，有总上限就用它补齐，没有总上限就按不限额处理。若最后一档明确返回有限上限、但产品总上限更大或为 `-1`，保留已知档位并标“阶梯结构未获取”，不计算整笔持仓收益。定期 APY 只取产品本金币种，不把其他币种奖励相加。
- Bitget 按 `apyType=single/ladder` 区分产品；最后一档上限字段未返回时按不限额处理；中间档边界缺失、坏值或断档仍标资料不完整。
- API 检查 JSON 保留 APR/APY、档位边界、申购上限字段及来源；产品池余额与申购上限分开。持仓检查不返回金额。

各平台已核实的产品字段与数值见[平台能力总表](PLATFORM-CAPABILITIES.md)。
